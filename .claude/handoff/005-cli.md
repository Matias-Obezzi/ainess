# Modo CLI: usar el orquestador desde la terminal

Repo: C:\Users\matia\Desktop\projects\ais
Rama: la activa (main), sin cambiar de rama ni crear otras

## Objetivo
Poder correr `ais "<prompt>"` desde una terminal y que ejecute el mismo ciclo de delegación que la app (misma config en `%APPDATA%\com.matias.ais\config.json`, mismos providers, mismo orquestador), imprimiendo la comunicación entre agentes en vivo y terminando cuando la tarea termina. Sin abrir ninguna ventana.

## Contexto
- Leer `PLAN.md`, `src/store.ts`, `src/lib/orchestrator.ts`, `src/lib/providers.ts`, `src/lib/tauri.ts`, `src/types.ts` y `src-tauri/src/runner.rs` (para replicar en Node exactamente lo que hace el runner Rust: spawn, líneas de stdout/stderr, kill del árbol de procesos, `NO_COLOR=1`).
- Hoy el store y el orquestador dependen directamente de `ipc` y `onRunOutput/onRunExit` de `src/lib/tauri.ts`, que solo funcionan dentro del webview. Hay que abstraer eso en un "transport" con dos implementaciones: Tauri (webview) y Node (CLI). El código de UI no cambia.
- `src/lib/detect` no existe en TS: la detección de binarios vive en Rust (`src-tauri/src/detect.rs`); para el CLI hay que replicarla en TS (mismas rutas: `claude` en `%APPDATA%\Claude\claude-code\<versión más alta>\claude.exe` y `~/.local/bin/claude.exe`; `agy` en `~/.gemini/bin/agy.exe`; después PATH con PATHEXT).
- Node es v25 (tiene `fetch`, `node:util` `parseArgs`, `crypto.randomUUID`, `node:readline`). Vite 8 (rolldown) está instalado y sirve para bundlear el CLI para Node.
- Windows: matar un proceso hijo debe matar el árbol (`taskkill /PID <pid> /T /F`), igual que hace `runner.rs`.
