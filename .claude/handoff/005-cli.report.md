# Reporte de Implementación: Modo CLI

## Qué se hizo
- Se abstrajo la capa de IPC (`spawn`, `kill`, `onRunOutput`, `onRunExit`, configs, detección de binarios) en una interfaz `Transport`.
- Se crearon tres implementaciones del transport: `tauriTransport` (para webview), `nodeTransport` (para CLI en Node) y `nullTransport` (para fallbacks).
- Se modificaron `store.ts` y `orchestrator.ts` para usar `getTransport()` y no depender directamente de Tauri APIs ni del chequeo de ventana webview (protegiendo el chequeo de `__ais`).
- Se creó `src/cli/main.ts` usando `node:util` `parseArgs` para aceptar argumentos por línea de comando o leer de stdin (el fallback si falta el prompt en CLI sin TTY). Se implementó la salida coloreada a la terminal en tiempo real suscribiéndose al store, el subcomando `agents`, los overrides de opciones y finalización limpia del proceso (códigos 0, 1, 2, 130).
- Se implementó en `src/lib/transport-node.ts` la versión Node de `detectBinaries` replicando la lógica exacta de `detect.rs`.
- Se configuró Vite y `package.json` agregando los scripts, un config `vite.cli.config.ts` de build SSR, y el shebang en `bin/ais.js`.
- Se agregó documentación sobre el uso por terminal en el `README.md`.

Se comunicó con Antigravity mostrando en vivo el flujo, y creó correctamente el archivo `hola.txt` en el temporal, terminando con exit code 0 automáticamente al acabar la tarea.

## Decisiones tomadas
- **setWorkspaceDir**: En lugar de no persistir desde el store globalmente, modifiqué la firma para aceptar `persist?: boolean` (default: `true`), y pasé `false` en el modo CLI para evitar guardarlo.
- **Detección de CLI Claude**: La lógica de `detect.rs` para parsear directorios por semver y resolver el mejor binario se tradujo manualmente a Node leyendo de `appData`.
- **Top-level await/Imports**: Se usaron dynamic imports `require()` controlados en `transport.ts` dentro de `getTransport()` para asegurar que Node modules no sean bundleados con la web.
