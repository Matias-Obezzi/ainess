# 更新日志

0.6.0 之前的版本记录在仓库的 CHANGELOG 里，为英文。

## 未发布

### 新增

- **窗口会以你离开时的样子回来。** 大小、位置、最大化或全屏：下次启动会在上次结束的地方打开，
  如果那台显示器还在，就在同一台显示器上，而不是每次都以 1400×900 出现在屏幕中央。窗口进入托盘时
  和应用退出时都会记录。

### 变更

- **点击你已经在的那个项目，会带你去它的编排者。** 第一次点击仍然在你离开的地方打开项目——看板、
  层级、某个聊天。对同一个项目的第二次点击以前什么都不做，现在会去编排者的对话：那是唯一没有回去
  的快捷方式的地方。

### 修复

- **同一个代理有两个进程。** 团队是每个代理只有一个实例的层级，但没有任何东西强制这一点。当实现者
  完成时，审阅者还在处理编排者交给它的任务，审阅却照样启动了——同一个审阅者上的第二个 `agy.exe`，
  写着同一段对话，两者同时运行多久就持续多久。现在一个代理只有一个进程：在轮次进行中到达代理的工作
  ——委派、审阅、对其提问的回答、重试——会记为排队中的运行，等该轮次结束后按到达顺序启动。编排者
  继续等它，看板卡片知道它，对话里会写明在等谁。停止该代理时，为它排队的工作也一并丢弃。

- **Telegram 机器人的令牌被写进了日志。** 每次向 Telegram 的轮询失败——断网期间每四十五秒一次——
  失败的 URL 都会被整个记下来，而 Telegram 把令牌放在那个 URL 的路径里：
  `api.telegram.org/bot<id>:<token>/getUpdates`。遮蔽器认识 `token=`、`Bearer` 和 `api_key`，不认识
  这种形状。现在应用两侧都认识了，到达日志文件的内容里不再带它。**如果你的日志文件曾经离开过你的
  机器，去 BotFather 撤销令牌并换一个新的**——旧的就在这个版本之前写下的每一个 `ainess-<日期>.log` 里。


- **规划者等待实现者的时候，弹出一个写着"idle"的红色 toast。** 文本是
  `root agent idle; waiting for 1 background task(s)`——Claude Code 在 stderr 上说它在等一个子任务，
  这正是它该做的事。CLI 写到 stderr 的每一行都被归为错误，而每个错误都会弹 toast。现在 stderr 的行
  按它本来的样子保存：在运行的活动里显示为一行普通的等宽文本；而 CLI 在结构化输出里真正点名的错误，
  仍然是错误，仍然是红的，仍然会弹 toast。


- **正在看的项目不再弹 toast。** 一条说"某个智能体委派了"或"某个任务完成了"的 toast，出现在那件事
  刚刚出现的同一条对话上，只是在它重复的东西上面盖了个框。窗口在前台、项目在屏幕上时会把它们压住；
  窗口在后台时照旧显示——那时它们是唯一的知情渠道。
- **关掉一个 toast 不会再把它后面的对话框也关掉。** toaster 从构造上就在所有对话框之外，而对话框把
  任何在自己之外的点击都当成关闭的理由。toast 不是在外面，是在上面。

## 0.16.0 — 2026-09-11

### 新增

- **`ainess mcp add|edit` 支持 `--header`。** 应用从 0.14.0 起就能给托管的 MCP 服务器传它要的
  header，CLI 却不行。现在可以用 `--header "名称: 值"`，可重复，在第一个冒号处切分，这样带冒号的
  值——URL、base64 令牌——能完整到达。`edit` 时新 header 会并入已有的，`--header "名称:"` 则删掉一个。
  header 是凭据，所以它永远不会进日志或输出：CLI 的启动行会遮住值，`--json` 打印 `***` 代替。

### 修复

- **验证里的"添加命令"按钮什么都不做。** 从 0.15.0 起就是这样。它给那一行传了个空命令，空命令在行
  被创建之前就被当成无效拒绝了，点击到此为止——一键建议能用，按钮不能。是这个应用有史以来第一个组件
  测试在它存在的第一天发现的。


- **智能体干活时说过的话，不会在它停下来的那一刻消失了。** 两个人从相反的两端报告了这件事——"它一
  委派，我的回答就没了，只剩下委派"和"活动一结束，中间的回答就丢了，只显示最后说的那一句"——其实是
  同一个 bug。

  有两样不同的东西承载着智能体的话。流承载它边说边说出的一切。`run.output` 是提供方的*最终*回答：在
  Claude 那里是 `result` 行，也就是最后一条消息，仅此而已。气泡显示的是 `run.output`。所以一个先解释
  自己发现了什么、再跑三个工具、最后以一次委派或一行总结收尾的回合，在它停下来的那一瞬间就丢掉了那
  一行之前的所有内容。

  其实从来没真的丢过：流就在通信消息流里，也在活动列表里。它只是不在任何人会去看的地方了，而且当一个
  回合一个工具都没用时，活动那一栏根本就不出现。现在气泡会显示整个回合，只有当最终回答说了记录里还
  没有的东西时，才把它接在后面。一对一聊天从另一头丢的是同样的东西——回合一结束，它的气泡就被最终回答
  覆盖掉了——现在遵循同一条规则。

- **Claude 的模型列表里没有 Fable，而且 `fable-5.1` 不是它的名字。** 这个列表是写在源码里的，不像
  antigravity 和 opencode 那样是去问出来的——所以它会悄无声息地变旧。手动输入也没用：Claude Code 对
  `fable-5.1` 的回答是 `unrecognized_model`，因为它接受的 id 是 `claude-fable-5-1`。两个都修好了。


- **应用在所有地方都会说七种语言，而不只是在有人记得的地方。** 有一百零七个句子写在了源码里而不是
  字典里：worktree 操作产生的每一个 toast 和对话框、隧道或安装失败返回的每一条消息、任务卡片，以及
  整个 CLI 包括它的帮助界面。七种语言里有六种拿到的是没人选过的语言，而且没有任何东西会注意到——所以
  才会攒到一百个：每一个在当时都只是一行。

  它们不是同一类东西。用户读的那些搬进了字典。只有开发者会读的那些——所有日志行——现在是英文：日志会被
  grep、被贴进 issue、被正在排查的人读，把它翻译掉就等于让除了那个语言的人以外所有人都用不上。

  CLI 的帮助是每种语言一条，而不是二十四条，因为它的各列是对齐的，而保持对齐是一个按语言来的决定：
  德语比日语更占地方，二十四条分开的条目会让其中某一条悄悄错位，而且没有东西能显示出来。

  现在也有东西会注意到了：一个检查，只要 `src/i18n` 之外出现读起来像西班牙语句子的字面量就失败，并且
  作为测试套件的一部分运行。它找的是西班牙语而不是文本，所以源码本身用的英文不会被标记。有两行是被
  允许的，每一行都写了原因：聊天的角色值会保存在聊天上并进入智能体的提示词，所以它们是数据，不是标签。

- **发消息的时候聊天变成空白。** 报告了四次，从没复现过，也从没留下日志——因为按大家找的那个意思，
  根本没有什么东西坏掉。没有抛异常，消息还在 store 里，切换项目就会回来，而这正是"东西还在、只是没被
  显示出来"的特征。

  在一条回答被写出来的过程中，对话每 150 毫秒会追一次自己的末尾，而这件事是用 `scrollIntoView` 做的。
  这个方法不是滚动*某一个*容器：它会从元素往上走，把**路上每一个可滚动容器**都滚动到需要的程度。而
  `overflow: hidden` 并不会让一个盒子不再是可滚动容器：它拿走的是滚动条和滚轮，`scrollTop` 照样管用。
  应用的外壳是 `h-screen overflow-hidden`，底下好几个盒子也是，所以一个内容比自己盒子高出几个像素的
  外壳，就会被那次调用滚动——然后就一直保持那样：没有滚动条，没有滚轮，没有任何东西能把它放回去。
  对话往上滑出了视野，就停在那儿，直到有什么东西强制重新布局为止——打开侧边栏、切换项目。

  它只在发消息时出现，因为那个循环只在有回答过来的时候才跑。而为了抓它而搭的那套装置从来没抓到过：
  它的传输层根本启动不了一次运行，所以它本该去压的那个循环一次都没有跑起来。

  三个消息流现在都是在自己本来就握着的那个容器上写 `scrollTop`，只碰那一个元素，上面的什么都不碰。
  它们还会在同一个节拍上检查自己上方有没有什么被滚动过——上面那些本来永远不该被滚动——并把它放回去，
  同时在日志里留下一行，说明是哪个盒子、动了多少。如果这件事再发生，这次至少有东西可以读。


- **改了一个项目的团队之后，它的规划者不会再往已经不存在的智能体身上派活了。** 一次委派是按名字去
  规划者的下属里找的，而规划者知道的名字来自交给它的系统提示。但会话是*恢复*的：CLI 会把之前那整段
  对话重放一遍，里面列着旧的团队，也做过针对那些名字的、当时确实成功的委派——而一份记录的声音，比
  贴在上面的系统提示要大。所以给智能体改名、换阵容、加一个实现者，都会让规划者继续对着一个不复存在
  的团队说话，活儿再以"委派失败"的形式回来。

  现在会话会带上一份记录，记着别人告诉过它什么样的团队：这个智能体的名字和它下属的名字，仅此而已，
  因为一次委派要对上的全部就是名字。当这份记录对不上了，下一轮就会开一段新的对话，而不是恢复到错的
  那段里去，并且会把这件事说出来。在这之前开的会话会被沿用而不是丢掉：解药不该是让每个项目里的每个
  智能体都丢掉自己的上下文。

- **一次委派里点名了一个不存在的智能体，那份活儿不会再无声无息地消失了。** 如果所有名字都错，这一轮
  会重来，那是对的。如果只错了*一部分*，对的那些就开始跑，错的那些在消息流里留下一条错误，而它们
  承载的那份活儿从此再没有人、也没有对谁、提起过。现在这些名字会一直被带到这一轮的最后，在规划者重新
  接手的时候摆到它面前，连同真正归它管的那份名单一起。而一个谁都对不上的名字，会被当成它本来的样子
  ——会话还记着一个更早的团队的证据——于是那段会话被丢掉，下一轮从真实存在的团队开始。

## 0.15.0 — 2026-09-11

### 新增

- **层级里的那些线现在真的能连了。** 智能体的卡片一直画着连接点——箭头就是从那里接出去的——但画布本身
  是不可连接的，所以它们看上去像是能拖的东西，实际上不能。现在从一张卡片拖一条线到另一张，就会把那个
  智能体挪到新的规划者下面。规则就是智能体编辑器一直在用的那几条——不能挂到自己下面，不能挂到已经在
  它下面的人下面，最上面只能有一个规划者——而且是从同一个地方读的，而不是再写一遍，这样两个界面就不会
  在"什么算一个有效的团队"上产生分歧。


- **一个项目可以自己说清楚"完成"是什么意思，而 ainess 会去核对。** 到目前为止，一个任务往前走，是因为
  智能体的进程以零退出。除此之外什么都不看，所以"完成"的意思只是"CLI 回来了"——而发现不是这么回事，
  是你第二天早上的活儿，一张卡片一张卡片地看。现在项目可以列出自己的命令（`npm test`、
  `npx tsc --noEmit`、`cargo check`），当一个智能体做完被委派的工作，这些命令会在它真正干活的那个
  文件夹里运行——如果它有 worktree，就在 worktree 里，这样测试看到的是刚写下的代码。通过了，卡片照旧
  往前走，有评审就交给评审。没通过，卡片就带着命令的名字和它打印的内容回到你这里，对话里出现一条消息，
  还有一个 `verify.failed` 钩子，好让手机在凌晨三点也能叫醒你。项目本来就声明过的命令——package.json、
  Makefile 或 Cargo.toml 里的 `test`、`lint`、`typecheck`、`check`、`build`——一键就能加上。

- **撤销一次运行做过的改动。** 一次运行本来就记着它发生在哪里、从哪个提交开始，因为差异面板需要这些，
  所以材料早就有了；缺的是知道这个文件夹*在那之前*已经有什么在手上。没有这一点，"撤销这次运行"和
  "把所有没提交的东西都扔掉"就是同一条命令，而它们并不是同一回事——后者会吃掉你自己做过、却从没提起
  的工作。所以现在一次运行也会记下开始时哪些文件已被修改、哪些没被跟踪，而一次结束的运行的详情里，
  多了一个把文件夹放回原样的按钮。

- **给一次运行的上限，而不只是给一天的。** 每日和每月的限额从来拦不住某一次运行一口气花掉一整天的额度：
  它们是总数，而总数只会在事后才察觉。现在项目还可以设定一次运行最多能花多少。

  这件事老老实实能做到什么，值得说清楚，因为它和你会想当然的不一样。这里的每个 CLI 都是在结束时才报告
  花费，而不是在干活的过程中——所以一次超出上限的运行没法在半路被掐掉，因为在它结束之前，应用根本不
  知道价钱。上限做的事情是拦住*下一次*：某次运行一报告自己超了，消息就会说出来，而这项工作不会再开始
  新的一轮。算的是整条链，不只是最后一次运行，所以两轮之前那次贵得离谱的委派照样能把它拦下来——否则
  上限就不再是上限了。设成"仅警告"的预算，依然只是警告。

  它是刻意保守的，而且在动手之前会把话说明白：哪些文件会恢复，哪些文件会因为之前并不存在而被删除，
  以及哪些它不会碰——那些在运行开始前就已经改过的文件，智能体的改动和你的改动在同一个文件里，从这里
  没法把它们分开。删除用的是给了明确路径清单的 `git clean`，绝不会放开手脚去处理整个文件夹。在这之前
  的运行也会显示这个按钮，把文件夹当作是从干净状态开始的——这是关于它们唯一能假设的事情。

  不会自动重试。智能体修不好的失败会变成一个跑一整夜的循环，而决定把活儿退回去是一个决定，不是一个
  反射动作。

  你输入的内容会当着你的面被拆成程序和参数，拆出来的片段就显示在输入框下面，因为它就是这样被启动的：
  在这里输入的任何东西都不会到达 shell。`&&`、管道和重定向会带着理由被拒绝，而不是被悄悄转义——应用
  跑在这台机器提供的那个 shell 上，而它们对怎么加引号意见不一。想用两条命令，答案就是加两条命令。
  没有列出命令的项目，行为和以前完全一样。


### 修复

- **一个已经委派出去的规划者，在实现者干活的时候也能跟它说话了。** 之前它会把你的消息压在队列里，
  一直等到整轮回来——于是那个工作就是继续做规划的唯一一个智能体，反而成了有活在跑的时候你唯一联系不上
  的那个。原因是一个词在做三份工作："等待"既表示在等一个回答，也表示因为额度用完而被挂起，*还*表示
  在等实现者——而只有最后一种说的是一个自己没有任何进程在跑的智能体。现在只有最后这种情况会接下消息并
  开始一轮；另外两种仍然入队，因为在那里开新的一轮，正好是在压过它正在等的那件事说话。

  让这件事不止是改一行的，是实现者在规划者正回答你到一半时回来的情况。同一个智能体的两次运行，就是两个
  人在写同一个 CLI 会话，所以结果会等那一轮结束，紧接着再交过去——任务自己的那条线优先，排在队列里其他
  任何东西前面。而一个在自己派出去的活还在跑的时候结束了本轮的规划者，现在显示为等待而不是空闲，因为它
  本来就是等待。

- **一个会永远问同一件事的智能体，现在会停下来。** 回答一个问题会让智能体从它原来所在的那一轮继续——
  问题并不会让轮次前进——而轮次是 `maxRounds` 唯一在数的东西。所以一个用另一个问题来回应每一个回答的
  智能体，根本没有任何东西约束它：你回答，它再问，唯一能结束的方式是你放弃。自主模式注意到了这件事，
  给自己加了上限，但只针对它自己回答的问题；当回答的人是你的时候，哪里都没有上限。

  现在有两条规则。这个任务已经回答过的问题不会再问一遍：答案有记录，所以直接交回去，这不是一个需要
  斟酌的判断。而一个已经问了十二次的任务会停止提问并说明这一点，因为十二轮原地打转是一个糟糕的下午，
  而一整夜这样更糟。问很多*不同*的问题依然允许：受限的是次数，从来不是内容。


- **应用不再把它拥有的每一秒都花在给自己写文件上。** 一个项目的历史，只要里面有任何变化就会被整个
  重写，而且在写之前会先读回来并解析，免得丢掉在 CLI 或手机上做出的决定。对一串消息来说这很便宜，
  对一串 CLI 的原始输出来说则是灾难——而历史差不多已经变成后者了：在发现这个问题的机器上，某个项目
  的文件已经长到 **47 MB，其中 83% 是原始行**，一次保存要在界面自己的线程上算 283 毫秒——每秒两次，
  只要有智能体在工作就一直如此。也就是每一秒里有 566 毫秒花在思考而不是绘制上。这正是为什么恰恰在
  有东西可看的时候应用会变慢，也是为什么发一条消息之后对话会一片漆黑，直到随便什么事情——打开侧边栏、
  切换项目——逼它重新绘制为止。从来不是动画，也不是智能体的输出涌进来：智能体每秒只打印一两行。是应用
  在跟自己的硬盘说话。

  旧的上限只数行数，不看行有多大，量错了东西：行的中位数是 313 个字符，量到的最大一行有 536 KB。
  现在一行在 2 KB 处截断，一次运行保留其中 64 KB，而且只有最近三十次运行会保留原始行——更早的运行
  保留它们的指令、回答和花费，失去的只是 CLI 当时怎么说的那份记录。同一个文件变成 7 MB，一次保存
  只要 44 毫秒。再加上智能体工作期间保存改为等三秒而不是半秒，界面从 **每秒 566 毫秒降到 15 毫秒**。
  已有的历史不用做任何处理：第一次保存就会按新尺寸重写它。


- **后面什么都没写的选项，不再被当成它自己的值。** `ainess hook add --action slack --url
  --template "..."` 里 `--url` 后面什么都没有，之前会把「这个选项存在」这件事本身写到 Webhook 地址
  的位置上，hook 就这样指着一个没人输入过的东西被保存下来：它哪里都送不到，也从不说为什么。现在它
  会停下来，告诉你缺了 `--url`——本来就是缺了。`--program`、`--args` 和 `--template` 也一样：后面
  什么都没有的选项，是你忘了填的选项，不是一个值。
- **没有会话 id 就开始的 Claude 回合，现在会开一段新对话，而不是去恢复一段空的。** ainess 会记住
  提供方通报的 id，好让下一条消息接着同一条线走下去。没有带 id 的开场行以前照样被记下来，记成「什么
  都没有」，于是下一个回合请求 Claude 恢复一段没有名字的会话。这样的行现在会被忽略，下一个回合便干净
  地开始——反正它本来也会走到这里，只是路上少了一次失败的恢复。

## 0.14.0 — 2026-09-11

### 新增

- **托管的 MCP 服务器现在可以拿到它要的请求头了。** ainess 把一个 http 服务器写进会话配置时，只写了
  类型和 URL，别的什么都没有——所以任何躲在 bearer 令牌后面的东西根本就够不着：放令牌的那个字段压根
  不存在。现在有了：在 http 服务器上，一行一个请求头，`名称: 值`。值按**第一个**冒号切开而不是最后一
  个，因为值自己就带冒号（一个 URL、一个时间、一个 base64 令牌），从末尾切会把半张凭证交给服务器——这
  种故障要很久以后才浮现，变成一个没人会追溯到标点符号上的认证错误。写 `Bearer ${你的变量}`，客户端
  会在连接时从环境里把它展开，于是密钥本身永远不会进到配置文件里。Antigravity 也拿得到，走
  `agy mcp add --header`，参数名和参数值是数组里分开的两项，绝不拼接出一条命令行。而当这条命令失败
  时，它的输出会在去掉凭证之后再拿给你看：消息仍然点名是哪个服务器失败了，而那本来就是唯一有用的部
  分。

### 修复

- **向 Antigravity 查询剩余额度时，不会再自己弹出一个终端了。** 应用在启动时占用一个控制台并把它隐藏
  起来，好让智能体接着运行的一切都继承它，从而在任何层级都不会弹窗。短查询也在继承它——而隐藏一个控
  制台的前提是 `ShowWindow` 能作用到真正显示它的那个窗口，而在 Windows 11 上，默认控制台宿主是独立进
  程里的 Windows Terminal，它作用不到。于是一个画加载动画的子进程就会把那个窗口带到前面来，而
  `agy models` 正好画了一个。现在查询不再获得控制台：这正是版本检测和清理命令一直都在传的那个标志。
  智能体本身没有变——真正需要继承控制台的是它们，因为它们下面还有一整棵进程树。

- **环境变量那一栏在 http 服务器上是有用的了。** 它本来就画在那里，却哪儿也不去：会话配置的 http 分
  支从来没写过 `env`，所以在 http 服务器上填进去的密钥只会被存进配置文件，然后就没有然后了。一个
  http 的 MCP 服务器没有自己的进程，但智能体有——而智能体的环境正是 MCP 客户端展开请求头里
  `${VARIABLE}` 时要去看的地方。现在它们就进到那里。把密钥填进这一栏，在请求头里写
  `X-Goog-Api-Key: ${你的密钥}`，不用动机器的环境，也不用重启任何东西就能连上。这一栏也写明了代价，
  因为它比看上去要宽：放在这里的变量属于智能体的进程，所以每一个会展开变量的 MCP 服务器都看得到它，
  智能体运行的一切也看得到。它换来的是把密钥放在应用里而不是放在 Windows 里；换不来保密。stdio 服务
  器的变量原样不动。
- **输入框不会再为一个静止的会话每秒重绘两次了。** 一个会话是否正在作答，存在聊天模块自己的内存里而
  不在 store 里，所以没有任何东西能对它作出反应：只要还开着一个会话，输入框就用一个 500 毫秒的定时器
  反复去问，不管有没有事情在发生。现在它是订阅的——输入框只在一个回合开始或结束时重绘，别的时候不
  重绘。

- **打字快不会再让整个应用为每个字母干一遍活了，而且崩掉的面板会说是什么崩了。** 你打的字属于这段对
  话，所以它存在 store 里——而且每敲一下键就往那里写一次。store 每写一次，都会跑一遍每个订阅者的
  selector，于是每一个字符都会重新执行所有已挂载页面的 selector，并重新渲染它们喂出来的东西。现在输
  入框是本地的，store 在它背后被写入：打字时合并延后写，而在有东西不能丢的时候立刻写——被清空的输入
  框、切换对话、离开页面。另外：这个应用从来没有任何 error boundary，所以一个渲染错误会把整扇窗口一
  起带走，没有消息，日志里也什么都没有——因为本该记下它的东西也一起死了。现在会话和输入框各自是一道
  边界。抛错的面板会把故障留在自己里面，把错误显示出来，并把调用栈写进日志——这就是"能被报告的 bug"
  和"只能描述成屏幕变黑"之间的差别。

- **空的输入框不会再把两句话画在同一行位置上了。** 灰色的建议是画在输入框背后那一层上的，那一层带着
  和输入框一样的内边距，好让它和你打的字严丝合缝地对齐——而一个空的输入框正是从那个点开始的，那里也
  正是占位文字所在的地方。于是当智能体的上一条消息以一个是非问题结尾、而你还什么都没写时，"Sí,
  dale"和"Escribí mientras trabaja…"就被叠印在一起，两句都读不了。现在这个位置归建议：告诉一个空输
  入框该拿它怎么办本来就是占位文字自己的活，建议只是把这件事从泛泛而谈换成了手里握着这段对话去做。
  轮播的提示也出于同样的原因、在同样的位置让开。

## 0.13.0 — 2026-09-10

### 新增

- **新建的智能体一出生就自动批准自己的工具，而 CLI 仍然可以说不。** ainess 是以无人值守的方式启动这
  些 CLI 的：进程前面没有人坐着回答它。以扣住权限的状态创建出来的智能体，会以 `--permission-mode

  然处于待处理状态，选项必须是这个问题真正拥有的，所以昨天那条消息里残留的旧按钮不会把同一件事再决

### 修复

- **`ainess agents edit` 不会再悄悄撤掉你设好的权限了。** 每个编辑入口交给 store 的都是一个完整的智
  能体，store 会用它替换掉旧的那个——所以这个入口没有构造进对象里的字段并不是"保持不动"，而是没了。
  CLI 用它自己的参数来拼这个对象，而它没有委派审批覆盖的参数，没有 worktree 的参数，也没有配额重试
  的参数。于是 `ainess agents edit Impl --model x` 会把一个设成"从不询问"的智能体退回到跟随全局设
  置，而全局设置开着的话，它在下一次收到委派时就又开始要审批了。现在一次编辑是叠在原来那个智能体上
  的：它点了名的赢，它没点名的保留。而且即使值是"跟随全局设置"，点名也算数——那个值是以"什么都没
  有"的形式传过来的，并且必须能够擦掉一个"从不"。

- **往聊天里发一条消息，不会再让整个聊天变空了。** 加载一段对话就是读一个文件，而读文件需要时间。在
  那段时间里有三件不同的事情会出错，而三件事的结局是一样的：历史消失，直到你离开这个聊天再回来——回
  来这个动作本身就是重试那次读取。在读取还在路上时发出的消息，会被一个在它出现之前就写好的文件覆盖
  掉；现在内存说了算，读取期间到达的东西会被保留。失败的读取没有被接住，而是从加载器里抛了出去，让
  聊天在内存里什么都不剩；而它失败的理由可以非常平常，比如正好撞上同一个文件在被写入。还有，一次重
  新加载会把三个灰色骨架盖在明明就在那里的历史上面，那看起来就像对话丢了。

## 0.12.0 — 2026-09-10

### 新增

- **智能体工作时排队的消息现在合并成一条一起发出。** 以前它们排成一列走：第一条在本轮结束时发出，
  第二条要等*那一轮*结束。一口气写下的三行变成了三轮——三次运行、看板上三张卡片，还有一个在读到第

  去：中间只隔一个空行，就像你自己那样打的。"立刻发送"也一样，所以为了送出三条中的一条而打断一轮，
  不再等于三轮；按钮从每行一个变成整块一个，而每一行在发出前仍然可以单独撤回。

- **只显示智能体此刻在做什么，一行。** 一个在干活的智能体每用一个工具就写一行，长的运行会写上几
  百行：会话被它已经做完的事填满，而唯一值得读的那一行——它*此刻*在做什么——被埋在上面某处。现在
  这些步骤从一条跑马灯里走过。它只有一行高且溢出被隐藏，所以刚做完的那一步从顶部离开，新的一步从
  底部进来。这个移动本身就是重点：一行原地替换文字，改一次和改四十次看起来一模一样，而"这东西还
  在跑吗"正是一堵静止的文字墙让人产生的疑问。点这一行，历史就在它上方展开；再点同一行，就收起
  来。有三样东西永远不折叠：智能体自己的文字、错误，以及它委派出去的那个智能体的卡片。那张卡片上
  载着需要有人回答的审批，为了会话整洁而把它藏起来是不值得的。

- **输入框会把你的句子写完，Tab 接受它。** 两件事，都在你自己的机器上算出来，都不会被送到任何地方。
  当输入框是空的、而智能体最后一条消息以一个是非问句结尾时，答案会以灰色出现：Tab 接受，Enter 发送。
  已经开始写了的话，它会用你在同一段对话里写过的内容来补全——你上次是怎么说的，就从头几个字符起再递给你一次。
  一个要你做选择而不是要一个“是”的问题不会得到任何建议，因为对“哪一个？”来说“是”是错的答案；
  做这个判断的词表是往沉默那边偏的。别的项目的内容永远不会出现在这里，和共享上下文同一条规矩。
  Tab 只在 `@`/`#`/`/` 菜单和 ``` 代码块都表过态之后才动手，而 Enter 完全没动：接受和发送仍然是两个决定。

- **有东西在等你回答时，任务栏按钮会闪烁。** 一个批准或一个提问会让智能体停在那里，直到你回来；
  在此之前，唯一知道的办法就是一直盯着。只有当窗口不在最前面时才闪，而这个判断放在窗口那一侧做，
  而不是先问一遍再动手：这两步之间用户可以点回来，而对着一个正在看窗口的人闪烁的任务栏，
  比不闪更糟。只有这两种：完成的任务是消息，不是停下的智能体。

- **侧边栏会标出正在无人值守运行的项目。** 自主模式开着时，名字旁边有一弯月亮。它本来就是按项目的
  ——开关只作用于那一个项目——只是唯一说明这件事的地方在项目内部，而这恰恰对你没在看的那个项目没用。

### 修复

- **一次问了三件事的回合，只回答一次。** 智能体可以一次问好几个问题，而每个答案都会各自把它的运行
  重新拉起：一个回合变成三次运行、看板上三张卡片、同一个工作区里三个智能体，而这些问题你是一口气
  答完的。现在它们成组出现——每个问题一个标签页，答好的打勾，只有一个按钮，只要还差一个就按不下去。
  回去的是一条消息，带着每个问题和它对应的答案，因为第二个答案离开它所属的那个问题，对智能体毫无用处。
  来自另一次运行的问题会等自己的回合，而不是挤进这一组。

- **等待配额的运行不会再没完没了地自我重启。** 等待中的运行会在配额回来时被重新拉起，而触发这项检查的
  时机之一是“上一个运行刚刚结束”——于是一个重新拉起后又用尽配额的运行会再次进入等待、再次被检查、
  再次被拉起，快到只受限于 CLI 失败的速度，每转一圈就往会话里写一条消息。有两处不对。这件事已经试过
  几次的计数放在等待条目上，而重新拉起它恰恰要把这个条目扔掉，所以每一次尝试读起来都像第一次。
  另一处是，一个只说“用完了”却不说原本有多少的服务商——Antigravity，它的池子只会说“agotado”和一个
  重置时间——在汇总里出来是“不知道”，而任何在问“配额回来了吗”的人都会把这个读成“是”。现在最多三次，
  之后它会说明并等你。

- **智能体干活时应用不再变卡。** CLI 打印的每一行都会被追加到它在 store 里的那次运行上，
  在整个运行期间每秒十二次。有八个界面订阅了运行的映射表——包括你打字的那个输入框——所以它们全都
  以这个频率重绘，而且是为了一个屏幕上没人在读的缓冲区：那些原始日志只在一个对话框里出现，
  而且只有你打开它时才出现。现在它们被另外存着，在运行结束时一次性写回运行本身，于是运行进行期间
  那张表就不动了。对话框依然能实时跟着看，运行中途崩溃日志也照样留在磁盘上。顺带还有两处：
  没有文本的刷新不再把整条会话重写一遍再原样放回去；层级视图的节点也不再随每个增量重绘——
  现在每个节点只盯着自己那个智能体最后一次工具调用，而它在两次调用之间是不动的。

- **重启时正在工作的项目会说出来。** 在委派进行到一半时更新应用，重新打开，去看层级视图——它看起来
  就像一个从来没发生过任何事的项目：所有智能体都空闲，什么也不说。运行记录一直都从磁盘恢复回来了，
  会话里也显示着；层级视图读的是每个智能体的运行时状态，而重启只用团队信息来搭建它。现在每个智能体
  会带着它被打断时正在做的任务回来，标记为已停止——不是失败了，是应用走开了。已经被这个进程派去干活的
  智能体不会被碰：恢复是异步的，把一个已死运行的任务盖在一个活着的运行上，描述的就是另一回事了。

- **右边的面板属于你当前所在的项目。** 在一个项目里打开终端面板，再走到另一个项目，它在那边也还开着
  ——而且标签栏是空的，因为终端是第一个项目的。现在三个面板都按项目记住：离开时收起来，回来时再拿出来，
  从没开过的项目就一直是关着的。


## 0.11.0 — 2026-09-10

### 新增

- **项目的三个视图变成了侧边栏里的行。** 编排器、任务、层级原本是顶栏里的一个分段控件——而那条栏还得放下
  项目名、分支、花费、自主模式开关和所有面板按钮。它们是导航，而导航就住在左边那一列。每一行打开它自己
  名字对应的视图，而不是把你留在项目上次停下的地方。

- **快捷命令可以是你自己的。** 在检测到的脚本旁边，现在有地方添加那些没有任何文件声明的命令：docker
  compose 那一行、隧道、只有这个项目需要的迁移。它们保存在项目里，排在菜单最上面。

- **窗口栏会告诉你聊天渠道连上了。** 在手机图标旁边，只要 Telegram、Discord 或 Slack 真的在运行，
  就会亮起——这个问题以前得打开设置才能回答。它不是开关：启用一个渠道需要令牌，还需要一份谁可以说话的名单。

- **终端面板把项目自己的脚本做成了按钮。** 启动开发服务器，以前是开一个终端，再把项目里早就写好的东西
  重新敲一遍。现在面板会去读它：package.json 的 `scripts`、Makefile 的目标，以及 cargo 常用的那四个。
  每个一个按钮，最常用的排在前面——dev、start、build、test。每个都开自己的标签页，名字用脚本名而不是
  “PowerShell 3”，所以放着服务器的那个标签页是找得回来的。按一个已经在跑的脚本，它会带你过去，
  而不是再起一个去抢端口然后败下阵来；正在跑的会有一个绿点。包管理器由锁文件决定，因为在 pnpm 的
  工作区里用 `npm run` 会解析出另一棵树。名字不是普通名字的脚本根本不会出现：这些字符串会被打进真正的
  shell，`predev && curl x | sh` 会照着字面跑起来。

- **依赖关系图现在从一个任务里打开，只显示这个任务的家族。** 它以前是整个看板的第二个视图，把项目里所有的
  链条并排画出来：宽得超过窗口，而“这个任务到底跟什么缠在一起”的答案就埋在中间某处。现在它从任务本身打开，
  屏幕上就是这个任务在等什么、谁在等它，一路传递下去——别的都没有。只是碰巧共用一个前置条件的任务算兄弟，
  不算家族，会被挡在外面；正是这些兄弟让原来的图没法看。点一张卡片，图就挪到它身上，于是一条链可以一步一步
  跟下去。归档的任务也会一起出现：一个归档的前置条件，仍然是它下面的东西无法开始的原因。

- **把对话退回去，或者改写你问过的话。** 在聊天里右键点任意一条消息，对话就可以停在那里；如果是你自己
  发的，还可以改写它，从那里重新问。后面的内容会消失，智能体的会话也会消失——你看到的那条线索只是对话的
  一半，另一半是智能体自己的记忆，把你刚收回的东西留在它那里，会让这条线索对"下一个回答建立在什么之上"
  这件事撒谎。对话框会在按钮之前把这些说清楚，而不是之后。退回到最后一条消息是灰的，因为它什么也带不走。

- **自主模式，带自动关闭的时刻。** 项目栏里的按钮可以开启 1、2、4、8 或 12 小时。开着的时候，
  项目不再等你：需要你批准的委派会被批准，提问会按最保守的方式自己作答，轮数上限也不再结束任务。
  没有“永远”这一档——到你设定的时刻它自己关闭，手动停止照样能停。项目的花费上限和以前一样有效，
  那才是刹车。一个只会提问的任务也吃不掉整个晚上：自动回答十次之后，提问重新回到等你的状态。
  结束时，它把报告留在会话里：完成了什么、失败了什么、替你批准了什么、替你回答了什么。

- **配额回来时重试。** 因为模型配额用尽而失败的运行，会把活儿擂在半路，直到你回来手动点重试。
  现在每个智能体都有自己的开关：配额用尽时，运行不再算失败，而是等着，等供应方有空位就用同样的提示
  自己重新启动。自主模式下无论开关如何都会这样。如果配额回来时开关已经关了，或者自主模式已经结束，
  就不会重启任何东西——而且会告诉你，而不是默不作声。

- **Slack 也接上了，三个都齐了。** Telegram、Discord 和 Slack，在你本来就开着的那个里用同样的命令，
  每个在设置里都有自己的卡片和自己的聊天名单——在一个渠道被授权的聊天，就只在那一个里被授权。
  Slack 要两个令牌而不是一个：应用级的那个负责打开连接，机器人的那个负责发消息。这是 Slack 的设计而不是我们的，
  页面会说明哪个是哪个。你的 Slack 应用里必须打开 Socket Mode，机器人也必须被邀请进频道；这些页面上也写着，
  因为否则什么都收不到，而从这里没有办法告诉你原因。

- **Discord，和 Telegram 并排。** 两个里你本来就开着的那个，用的是同样的命令：你写的任何东西都会开始一个任务，
  `/status` 告诉你谁在干活，`/approve` 和 `/answer` 处理等着你的事。设置里现在每个渠道一张卡片。
  两个都不会把任何东西暴露出去——出去的是应用本身，所以依然没有隧道、没有端口、也没有可以被找到的地址。
  每个渠道只授权它自己的聊天：一个 Discord 频道 ID 不会因为出现在 Telegram 的名单上而获得授权。
  你的机器人需要在 Discord 开发者门户里打开消息内容 intent，页面上也会这么说，
  因为没有它消息会是空的，而从这里没有任何办法告诉你原因。

- **可以从这里开 pull request 了。** 智能体在自己的分支上做完，最后一步一直得你自己动手。
  现在 pull 和 push 旁边有了一个按钮，完成的卡片上也有。它绝不会一键就开：会有一个对话框告诉你
  哪个分支要合进哪个，标题和正文已经根据任务、以及智能体报告的内容写好了——它改过的文件、它验证过什么，
  还有它没能做到的事，那部分会带着自己的小标题出现，而不是被略过。在默认分支上它会拒绝；
  在还没 push 的分支上，它会问你要不要先 push，而不是背着你去做。

- **可以换一个模型、或者换一个智能体来重试一个任务。** 一次失败的运行，或者智能体在半路上把额度用完的运行，
  以前只能把整件事重新打一遍。现在运行自己的菜单——以及它卡片上的按钮——可以用同样的提示词、
  换成你挑的对象再跑一次。它从零开始，而不是接着那次出错的运行继续，因为出问题的往往正是那次的上下文。
  换智能体会把模型清空：一个提供方的模型不是另一个提供方的模型，把它带过去，就是把一次运行送去一个不存在的模型。

- **可以把文件拖到输入框里。** 回形针和 Ctrl+V 是原本的两个入口；从你本来就开着的文件夹里拖一个文件过来，
  是第三个，也是不用绕路的那个。当带着文件的拖拽经过时，输入框会描出一圈边框，而你已经写好的内容会跟着一起发送。
  正在从一列去往另一列的任务卡片不会被拦下——它带的是文本而不是文件，接住它也不会把它移到任何地方。

### 修复

- **很长的任务详情不再把其他所有东西挤出弹窗。** 智能体想写多少就写多少，而详情夹在状态字段和依赖、
  运行之间。现在它会折叠成几行，用一个“展开”打开。按钮需不需要是量出来的，不是从文字长度猜的：
  一段话占几行，取决于给它多宽。

- **项目的脚本是一个菜单，不是一排会横向滚动的按钮。** 在本来就窄的面板里排一行按钮就会出现横向滚动条，
  一个有二十个脚本的项目会把其中十九个藏在后面。现在它们是“+”旁边的一个菜单，和控制台选择器一个样子。

- **顶栏不再显示有几个智能体在工作。** 侧边栏里项目旁边的那个点，在它们工作时本来就在呼吸，
  而那正是你会去看“现在在发生什么”的地方。

- **自主模式的按钮和它周围的按钮长得一样了。** 它原本自带琥珀色填充，为了让人不可能看漏。其实不必：
  真正响亮的是栏下面那条横幅，它横贯整个宽度，而且只有模式开着时才存在。

- **通信面板换成了一个对话气泡。** 它原来的图标描述的是面板从哪里打开，而这是关于它最无关紧要的一件事。
  它装的是智能体之间说过的话。

- **看板的工具栏对齐了。** Button、Input 和 SelectTrigger 的默认圆角并不一致，所以用这三样搭出来的一行，
  会有两种圆角并排出现。现在高度和圆角都只有一种，写在每个控件上，而不是交给默认值。

- **回答一个问题，现在是勾一份清单再按一个按钮。** 选项原本是一排行内按钮，每个只有自己文字那么宽，
  几个排在一起参差不齐，一个单词的选项就只有那个单词那么大的点击范围。现在它们是一份清单，一行一个，
  和框一样宽。可以多选的问题会明说，而不是让你点第二下才发现。而且单选的问题不再是碰到选项就发出去：
  两种都等你按“回答”，于是即将说出口的话会先出现在屏幕上——点错了只是再点一下撤销，而不是已经送出去了。
  在单选问题里，选项和自己写答案的输入框会互相替换，因为一个答案不能同时又是另一句不同的话。

- **任务底部的按钮按用途站好了队。** 三个散着的按钮加一条“把它们分开”的规则，让“归档”孤零零地卡在中间，
  离一个把你带走的链接和一个删了不回来的删除一样远。现在，去别处的在左边，改动这个任务的在右边，挨在一起。

- **看板去掉了视图切换器，“新建任务”回到了它该在的地方。** 图不再是看板的第二个视图，也就没有什么可切换的了，
  于是两条工具栏合成一条：搜索、筛选、计数，最后是“复查”“复制为 markdown”和“新建任务”并排。

- **Antigravity 的配额会说明自己为什么是估算。** 别的服务商都显示数字的地方，它的圆环显示一个短横线，
  而旁边没有解释的短横线看起来就像坏掉了。它没坏：Antigravity 不报告还剩多少。确切的数字是存在的——
  它自己的 CLI 就在向 Google 索取——但它在付费的 Code Assist 许可后面，没有许可的账号会被拒绝。
  所以现在应用会把这件事说出来，就在短横线旁边，在输入框的弹出面板里、在智能体的界面里、在设置里，
  而不是让你自己猜。显示出来的内容仍然是从运行返回的“quota reached, resets in 1h45m”推断的，
  因为能读到的只有这个。

- **配额的圆环和进度条会随着消耗而变满。** 它们原本填的是*剩余*：没动过的配额是一个满环，快用完的反而
  几乎是空的——对于一个"正在被消耗的东西"的仪表来说完全是反的，这也是它们没法一眼看懂的原因。现在它们
  从空开始，随着你花掉而填满，旁边的每个数字也数同一件事：“83%”指的是已经花掉的，不是还剩下的。
  颜色仍然看剩余，所以一个快满的环同时也是红的：两半在同一刻说“快用完了”，而不是其中一个说得太晚。

- **步骤不用等浏览器就能说清它做了什么。** 智能体活动里的每一行都是被截断的——工具显示摘要，委派显示任务的
  九十个字符——而读到其余部分的唯一办法是浏览器画的 `title`：等上一秒，在指针碰巧落到的地方弹出一个光秃秃的
  小框，还把换行压成空格，而这恰恰是命令或调用栈最不该被这么对待的地方。现在它们用的是应用自己的提示框，
  贴在那一行上，等宽字体，换行原样保留。运行正在进行的那个步骤也有了一个——它以前什么都没有。

- **智能体不会再知道没人跟它提过的项目。** 共享上下文原本是设置页里的一段文字，会被贴到每个项目、每个
  智能体的提示里。你在里面写了某个仓库的事，所有地方的所有智能体就都读到了——一条发给某个项目的消息，
  就是这样在另一个项目里被理解、被执行、被带了过去。现在它属于每个项目：设置页里选是哪一个，
  `ainess context` 也和 CLI 的其他命令一样接受 `-p`/`-w`。你原来写的内容会被复制到你已有的每个项目，
  所以什么都不会丢；如果那段文字本来只关于其中一个，其余的项目现在就是你去清空它的地方。

- **钩子一开始就说你选的那个事件。** 十七个事件背后只有一条默认文案，是照着“某个智能体完成了”写的，
  而且写死成西班牙语。于是“断网”的钩子一上来就宣布某个智能体完成了，对所有人，用大多数人并没有选的语言。
  现在每个事件都有自己的开头一行，用你的语言，用那个事件真正携带的变量——提问时给你问题，配额用尽时给你模型，
  委派时给你两个智能体。在动这条消息之前换事件，消息会跟着换；一旦你动过它，它就不再跟着换，因为从那以后它是你的。
  测试按钮也用你的语言填变量，所以预览就是你真正会收到的那条消息。

- **应用不再随身带着六种它没在给你看的语言。** 七个词典原本都打进同一个包里，所以每次启动都要为
  没人在读的那六个买单：575 kB，压缩后 179。现在只有西班牙语是内置的——它是其他所有语言的兜底——
  而你的那一个会在第一次绘制之前取回来并留着。这个 chunk 从 575 kB 降到 83 kB，压缩后从 179 降到 27。

- **在聊天里回答问题的智能体，不能再派活了。** 承载你回答的那一轮在启动时，没有被告知它属于一个聊天，
  于是被当成任务来读：它的 `delegate` 块会被解析并执行。一个智能体可以在没人要求的对话里，
  把别的智能体支使起来。

- **拖动时看板也会向下滚动。** 比屏幕更高的一列，遇到的是看板在横向上遇到过的同一个问题：
  你想放到它下面的那张卡片在画面之外。现在指针所在的那一列也会跟着拉动，用的是同一条加速曲线。

- **智能体干活时弹出来的那些控制台窗口，这次是真的没有了。** 上一次的修复修的是错的那一半。
  要求一个「没有控制台」的进程，对那个进程是有效的——但接下来，由**它**启动的每个控制台程序都会向 Windows
  要一个，拿到一个全新的，而那个是看得见的。那些窗口从来就不是我们的：它们属于我们的智能体正在运行的程序。
  现在应用在启动时只为自己取一个控制台并把它隐藏起来，底下的一切无论嵌套多深，都会继承这一个，
  而不是各自去要一个。

- **回答里指向文件的链接现在有反应了。** 智能体写下
  `[这个文件](file:///C:/Users/you/notes.txt)`，得到的只是一段灰色的死文字：`file:` 和 `javascript:`、
  `data:` 一起待在被拒绝的名单里，可那两个是真的会在页面里执行的，而 `file:` 什么都不执行——它只是被顺手
  归到了一起。现在点击它会在文件管理器里定位到这个文件，然后就到此为止。它永远不会变成一个真正的链接，
  也不会被交给系统去打开，因为 `[看看这个](file:///C:/x.exe)` 是任何智能体都写得出来的一行。

- **把卡片拖到边缘时，看板会自己滚动。** 比窗口更宽的看板原本没法横穿：你想要的那一列在画面之外，
  而松手去滚动又会把卡片丢在你不想要的地方。现在把卡片停在左右任一边缘附近，看板就会跟着走——
  刚进入这个区域时慢，越靠近越快。而且你即使不动，它也会继续滚，这一点拖拽事件本身并不会告诉任何人。

## 0.10.0 — 2026-09-09

### 新增

- **输入框会补全你正要打的东西。** `@` 是项目里的智能体，`#` 是工作区里的文件，`{{` 是模板变量，
  而 `/` 把命令和你保存的指令放在一起——因为这两样都是你可以发起的东西。方向键移动，Enter 或 Tab 选中，
  Esc 关掉列表而不动你已经写下的内容。原本的两个命令之外又多了五个：`/tasks`、`/chat`、`/diff`、`/stop`，
  以及会先问一句的 `/clear`。在代码块里什么都不补全，因为那里的 `#` 是注释，`/` 是路径。

- **现在可以在输入框里写代码了。** 以前 Enter 就是发送，所以写一段代码块意味着每一行都要记得按
  Shift+Enter，还要指望自己没忘记把围栏闭合——输入框把 Markdown 当作纯文本显示，什么提示都不给。
  现在这些按键知道光标在哪里：在一行只有开头围栏的地方，Enter 会替你写上收尾的那行，并把你留在中间；
  在围栏里面，Enter 是换行并带上你的缩进，Tab 是两个空格；而你正在写的那段被围起来的内容会有一个底色，
  这样你能看见它从哪儿开始、到哪儿结束。在围栏里用 Ctrl+Enter 发送，因为单独的 Enter 已经不能了。

### 修复

- **一个问题只在一个地方问。** 它原本会在对话里冒出一个气泡，同时又占住输入框，两个都是活的，
  两个都是同一个问题。输入框留下它，因为那里你可以用整个输入区来回答。答完之后它会以一行只读的形式
  回到对话里——那是对话中唯一还记着它被问过的东西。

- **在输入框里回答，现在是真的回答了。** 智能体问你一件事，你选择在输入框里写回复而不是在问题自带的
  那个字段里，然后发送——可问题仍然开着。每次你重新进入这段对话，它都会再次盖住输入框；它还留在铃铛里、
  首页上和 `/status` 里；而提问的那次运行，仍在等一个它其实已经收到的答案，与此同时你的消息另起了一次运行。
  一个问了问题的智能体是停下来等你的，所以你接下来写的就是答案，不管你写在哪里。

- **首页现在每件事只说一遍。** 它本该是「有什么在等你」的那个页面，可旧的项目卡片网格还留在下面，
  于是一个正在干活的智能体会出现三次：在「正在进行」的列表里、在它所属项目的卡片里，
  以及那张卡片自己的计数里。每张卡片还各自带着「打开」「编辑」「删除」三个按钮，其中一个是红的——
  而这些事情，点击卡片本身和右键菜单早就能做。现在整个页面只有一种行：等你的、在跑的、以及项目，按这个顺序。
  项目那一行只显示一句状态，并且只在确实有东西的时候，才补上一小块计数，说明有多少在等你、有多少在跑。
  什么都不等你的时候，它会用一行话说出来，而不是让你自己去推断。

- **建议的技能是写给智能体看的，而解释是用你的语言写给你看的。** 「建议」背后的目录原本整个是西班牙语：
  名字、智能体真正会读的那些指令，还有列表里那一行说明。指令是代码——它们会进入智能体的提示词，
  也会成为项目文件夹里的一个文件——所以现在它们是英文的，和这个仓库的其他部分一样。
  写给你看的那部分则会被翻译，七种语言都有。并且有一个测试，在每种语言都齐全之前不会放新的建议进来。

## 0.9.0 — 2026-09-08

### 新增

- **按项目设置花费上限，以及烧完之前的提醒。** 用量页面一直能告诉你一个项目花了多少，却拦不住它。
  现在一个项目可以设每日上限、每月上限，或者两个都设，并且你来决定达到时怎么办：只提醒，还是不让新的运行开始。
  提醒在 80% 时到达——每天一次，不是每次运行一次——用量页面会对着最接近被突破的那个上限画进度条。
  数字依然只来自每个 CLI 真正报告的内容：不报告任何东西的提供方不计入总数，页面会把这一点说出来，而不是去估算。

- **钩子可以通过 Telegram 通知你，并且多了三个值得被通知的时刻。** 另外两个聊天动作都要你先去服务器上创建一个
  webhook；这个直接复用你已经在「即时通讯」里配好的机器人，于是「任务完成时通知我」就只是从下拉框里选一项。
  你可以指定一个聊天，也可以留空发给名单上的所有聊天——而且只发给名单上的，因为钩子不能成为绕过名单的后门。
  随之而来的还有三个新事件：智能体提了问题正在等待、评审要求修改、智能体额度用尽。

- **搜索面板现在能搜「说过的话」，而不只是名字。** 它原本按名字查找项目、任务、聊天和智能体——当天用是够的，
  可两周之后你记得的是一句话，不是一个标题。输入三个字符，项目消息流和所有聊天里的消息也会一起回来，
  由新到旧，每条都把你搜的词摆在这一行的中间，而不是把消息开头的内容摆出来。重音和大小写都不影响，
  作者在你那两个词之间敲下的换行也不影响。

- **一次运行的差异，而不是整个项目的差异。** 差异面板显示的是项目的工作树，它回答的是「这个仓库里正在发生什么」，
  而从来不是「这个任务改了什么」。现在每次运行都会记住它在哪里跑的——项目工作区，还是智能体自己的 worktree——
  以及它从哪个提交开始。于是打开一次运行的详情，就能看到从它开始以来有什么变动。在此之前的运行两样都不记得，
  它会直说，而不是猜。

- **智能体可以移动自己的卡片，也可以为途中发现的事情新建一张。** 看板一直是单向的：规划者读取它并分派工作，
  而真正干活的人连自己的卡片都看不到，更谈不上说自己卡住了。现在任何智能体都能在工作时留下一个 `task` 块——
  一种移动自己的卡片并追加一行细节，另一种为它遇到的、不归自己管的事情在待办中新建一张无人认领的卡片。
  它会在运行还在进行时就出现在看板上，而不是等到结束，待办里的卡片会写明是谁提出的。关闭一张卡片，
  依然不是智能体说了算。

- **可以从你本来就开着的聊天里操作这个应用。** 设置里多了「即时通讯」一节：把 Telegram 上 @BotFather 给你的机器人令牌粘进去，打开开关，然后给机器人发消息就行。你说的任何一句话都会开始一个任务，`/status` 告诉你谁在工作、什么在等你，`/approve` 和 `/answer` 处理需要你的事，`/stop` 停止一切。这不会把任何东西暴露出去：是应用主动出去问的，所以没有隧道、没有端口，也没有任何地址可以被人找到。只有名单里的聊天能下达指令，名单为空就谁都不授权，陌生人一个字也得不到回复——他的 id 会出现在设置里，旁边有一个授权按钮，你自己的 id 也是这样找到的。到达通知铃的内容同样会到达聊天，而在等你的那些还会告诉你该回复什么。

### 修复

- **和同一个智能体的两个聊天，重新变回两段对话。** 智能体只有一个放置会话的位置，而那里存的是最后开口的
  那段对话。你和一个正在聊的智能体再开一个聊天，回到第一个，它就用另一个的上下文回答你——而且聊天还会
  覆盖掉它自己的任务正在用的会话。现在聊天会把属于自己的会话交出去，而不是去读那个位置；提供方报告回来的东西，
  会存在它所属的那个聊天旁边；还没有自己会话的聊天会从头开始，而不是借用别人的。在聊天里提出的问题，
  回答它也留在那个聊天里。

- **在通讯筛选里把所有类型都关掉，视图现在真的会空。** 你发给智能体的内容原本是豁免的：不管筛选怎么说都会显示，
  而且它根本不在类型列表里，所以也没有办法把它关掉。按钮写着「类型 (0/8)」，面板却还在往外显示东西。
  现在一共十个类型，你自己的那两个也在其中，关掉就是关掉。而当把视图清空的是筛选时，它会这么说，
  而不是声称什么都没发生过。

- **通讯面板会按智能体的本意来读它写的东西。** 之前那些行显示的是原始 Markdown——星号、反引号、井号——
  而同样的文字在应用的其他地方都能正常显示。现在正文会被渲染：智能体说了什么、委派了什么、带回了什么，
  以及它的备注。工具行和 stderr 保持原样，因为像 `src/lib/__tests__/x.ts` 这样的路径，
  并不是要你把它的一半加粗的指令；而你自己敲的内容会按你敲的样子显示，就像聊天里已经在做的那样。

- **类型筛选在你使用它的时候会保持打开，也不会再把面板撑坏。** 选中一个类型就会关掉菜单，
  于是把消息流缩到两个类型意味着要开五次。而打开它的那个按钮，在你取消勾选之前写着「类型」，
  之后变成「类型 (7/8)」——一个更长的标签，而那一行里没有任何东西被允许为它收缩，
  于是整个面板变得比它所在的停靠区还宽。现在这一行会让步了，每条消息自己的那一行也一样：
  两个智能体名字、一个时间、一个标签和一个按钮，本来也在为同样狭窄的空间争执。

- **想看一条消息的原始内容，看到的就是那条消息。** 通讯面板里每一行上的那个按钮，原本打开的是整次运行——
  这个会话产生过的每一行 stdout——而这并不是点在某条委派上的人想要的东西。现在它显示的是那条消息：
  从谁到谁、什么时候、完整的正文，如果是一次工具调用，还有工具名、它的输入，以及它失败时的错误，
  并且有一个按钮可以把这些一并复制。整次运行还在，只是往里多一次点击，那本来就是它该在的位置。
  按钮现在也有了提示文字，并且出现在每一条消息上，而不只是背后有运行的那些。

- **拖动窗口不再卡住和跳动。** 运行一个外部程序——每分钟刷新一次的 `git status`、一次 `git diff`、
  一次 `--version` 探测——会一直占着那个负责泵送窗口消息的线程，直到程序结束。而 Windows 拖动窗口用的正是
  同一个线程上的模态循环，所以一次恰好撞上它们的拖动就会僵住，然后猛地跳到指针已经到达的位置。
  这些命令，以及配置和日志的读写，现在都跑在那个线程之外。保存配置还改成了先写在旁边再改名覆盖，
  这样谁都不会读到写了一半的配置。

- **这个应用现在到处都叫 ainess，包括可执行文件。** 它以前叫 `ais`，而旧名字活在没人会看的地方：Rust crate，
  也就是二进制文件——安装好的应用是 `ainess\ais.exe`，任务管理器、防火墙提示和启动项列表给你看的就是它。
  命令行也跟着搬了：`ais run` 和 `ais serve` 现在是 `ainess run` 和 `ainess serve`，`ais` 不再存在。
  你原有的东西一样都不会丢：草稿、面板宽度和手机上的令牌都以新名字保存，并且仍然会读旧的。

- **不会再有控制台窗口在你正看着的东西上闪过。** 停止一次运行、关闭应用、一次超时的运行、关掉隧道，
  以及每一次对陈旧进程的检查，都会调用 `taskkill` 或 `tasklist`。而 Windows 会给一个由窗口应用启动的控制台程序
  分配一个控制台窗口，除非明确告诉它不要。启动智能体的那些调用一直都说了；它们周围做清理的那些没有。

- **输入框旁只剩一个按钮，而且它就是此刻该有的那个。** 没有任务在跑时是发送，智能体正在回答时是停止——两个按钮不再挤在你正在写的文字上面。底下什么都没变：Enter 仍然发送，智能体工作时仍然把你写的内容排进队列、等这轮结束再发出——现在这件事由空着的输入框告诉你，而不是第二个按钮。

- **智能体的提问会占据输入框的位置。** 它原本待在这次运行的气泡里：你正看着它时有用，一往下滚就没用了——更糟的是，有问题挂着时你在输入框里写的内容会开启一次新的运行，让智能体一直等一个永远不会来的答复。现在问题就站在你本来要打字的地方，选项是按钮，也留了地方写你自己的答案；有多个在等时它会说明，并且一次来一个。点「写点别的」就把输入框还给你，什么也不回答。

- **点击面板外部时，通知面板会关闭。** 它挂在标题栏上，而标题栏正是拖动窗口的区域：那里的点击会被系统拿去移动窗口，永远到不了负责关闭浮层的那一层。

- **终端属于它的项目。** 你在一个项目里开了终端，切到另一个项目，看到的还是第一个项目的标签页——这也是为什么终端看起来像是在错误的目录里打开：那是另一个项目的 shell，待在它自己的目录里。现在每个项目只显示自己的标签页，并记住上次看的是哪一个。删除项目仍然不会杀掉它的 shell，和以前一样——其中一个可能正在做什么——它们会出现在首页，那是没有项目的终端该待的地方。

## 0.8.0 — 2026-09-08

### 新增

- **空白的输入框现在会说话了，而且还会变。** composer 的占位符会打印五句话中的一句，并且每隔几秒钟就会切换：团队是做什么的，可以向他们交办什么，`/` 可以打开命令，以及回车键快捷键。它不再是输入行上一条永久的小尾巴，而是变成你只读一次的东西。对于那些要求系统减少动画的用户，它会保持静止；而在手机上，它完全不会动。
- **让动画只在有意义的地方出现。** 一个仍在运行的执行过程，不再使用旋转的加载图标，而是会有一道光在当前步骤上扫过；主页的 "工作中" 看起来像是活的；审批提示框周围会有一圈光线环绕，而且只在它等待你回复的时候才会出现；使用面板中的金额会向上滚动直至实际数值，并使用与表格相同的货币格式。除此之外，没有添加任何其他装饰：线程、信息流和看板都保持静止，因为你整天盯着看的工具，只应该在它向你传达信息时才动。
- **代理在完成任务之前也能说点什么了。** 到目前为止，被委派的代理能告诉其规划器的唯一内容就是它的最终答案：如果它在第二分钟卡住了，那二十分钟内都没人知道。现在，它可以在工作时留下一个 `note` 块——遇到了阻塞、比预期慢、或者你应该现在就知道的事情——并且应用会在执行过程中将其传递到信息流中，并交给委派这项任务的人。
- **并用它实际做过的事情来收尾。** 一个 `result` 块，指明它修改了哪些文件、运行了什么来测试它们，以及它没能做到的事情。文字说明依然保留；这部分内容规划器读起来不用去猜测其含义，并且它会在执行详情中以三个简短列表的形式出现。
- **在主页就能看到什么在等你处理。** 在项目列表上方，有两个跨越所有项目的列表：一个是等待你处理的内容——比如因为需要审批而暂停的委派、没人回答的问题，或者看板留在 *需要你处理* 状态的卡片；另一个是谁现在正在工作，在做什么，从什么时候开始的。每一行都会带你到对应的位置：审批或问题的线程，或者打开了任务卡片的看板。当它们里面没有内容时都会消失，所以一个安静的主页看起来和以前一样。而那个用来标记你上次打开的项目的徽章也不见了：你在主页正是因为你不在那个项目里。取而代之的是，每张卡片会说明里面正在发生什么："2 个工作中 · 1 个等待中"。
- **在同一任务上的代理会知道彼此的存在。** 之前，当规划器在两个实现者之间分配工作时，他们都是盲目启动的：谁也不知道对方在那，两人都去修改同样的文件，最后规划器收到两个相互矛盾的回答。现在，每个人都会被告知还有谁在处理同一个任务，以及他们被要求做什么——而且别人手里拿着的东西是归别人改的，不是让你去覆盖的。就像看板一样，这些信息在每一轮都会传递，因为这是在工作过程中会发生变化的信息。
- **Hook 现在可以写给“老板”，而不是指定某个人。** 发送指令的代理现在提供了层级顶端的选项——项目的根规划器，也就是 composer、CLI 和手机默认发送指令的对象。这个目标会在 hook 触发时才解析，而不是在保存时，所以即使团队重新调整，它也永远不会指向一个已经不再负责的人。如果不加过滤，它会触及*每个*项目的老板，这使得一个定时 hook 就足以覆盖所有项目；如果缩小到某个特定项目，它就会发给该项目的老板；而由代理引发的事件，也会留在这个事件发生的项目里。

### 修复

- **现在可以在代理还在写回复时向前阅读对话了。** 在聊天中，代理发送的每个增量都会把你拉回底部：直到它写完，你都不可能向上滚动去查看它两分钟前说了什么。现在，聊天的行为和编排器线程一样了：它只在你处于底部时才跟随底部，当你不在底部时，角落里的一个药丸状按钮会告诉你收到了多少条新消息，并能在你想要的时候带你过去。这个计数现在同时出现在这三个地方——聊天、线程和通信流——而不是只有光秃秃的“新消息”。
- **过长的模型名称不再会让新建聊天对话框破版。** 参与者那一行是由三个下拉菜单和一个垃圾桶组成的网格，而网格列的宽度不会缩得比其内容还窄：如果你选择了一个名字很长的模型，那一行就会被撑长，对话框也跟着撑长，最后名称和模式的字段就悬在了卡片外面。现在这些列可以缩小，名称也会被截断显示。
- **代理内部的工具报错，不再看起来像是应用坏掉了。** Antigravity 的 `view_file` 失败了，代理重试并继续运行，而对话中却会显示一个红色的警报，看起来和真正的系统故障一模一样。现在，它变成了执行活动中的一行，颜色是琥珀色，只需悬停就能看到提供商返回的提示。红色保留给真正坏掉的情况。唯一值得大声说出来的情况仍然会被提示：如果同一个工具在一次执行中失败了三次，说明代理在原地打转，系统会用单独的一行并指明该工具来告诉你。
- **composer 的按钮不再挤在输入框里了。** 发送按钮不再会变成一个时钟——排队的机制和以前完全一样，当代理忙碌时按下 Enter 键依然会排队，并且提示框也会说明这一点——同时附件回形针被移到了底栏，孤零零地在左边，而代理、模型、审批和配额则聚在右边。
- **在任何语言下，当任务失败时 `ais run` 都会报错了。** 之前它决定退出代码的方式，是在信息流中寻找西班牙语的 "CLI not found"——自从这些消息开始由词典输出后，那段文本就不存在了。在英语环境的机器上，一个因为缺少 CLI 而死掉的任务会以 0 退出，导致调用它的脚本以为一切正常（绿色）。现在它会读取执行记录来判断。
- **对话不再整体重绘了。** 线程和通信信息流以前会绘制它们拥有的每一条消息——每个项目三千条——而且没有一行被记忆（memoized），因此只要有任何东西触碰到 store，它们就会全部重绘。现在，它们只绘制最后一段，顶部有一个可以往回追溯的链接，并且它会保持你当前的位置而不是直接跳走。每一行只在确实有变化时才会重绘。
- **代理打字不再因为你工作的时间越长而消耗越大了。** 之前 CLI 发送的每一个增量都是一次写入操作：复制整个消息列表只为了在最后加上一个字母，加上为原始文本复制一次执行映射表，再加上遍历每一条消息来决定保存什么。每个 token 都来一遍。如果历史记录很长，这种工作量与曾经说过的所有话成正比，这正是为什么到了下班时间窗口会变得越来越卡的原因。现在这些增量会被收集起来并一起应用，最多每 80 毫秒一次，并且在一次执行结束或被停止时当场刷入，所以不会有任何延迟或遗漏。
- **项目会以你离开它时的样子打开，包括对话。** 切换到另一个项目然后再回来，会把你丢进编排器线程里，即使你之前正在该项目的一个聊天里说话：侧边栏请求的是项目*且没有聊天*，而它得到的正是如此。现在每个项目都会记住它最后的对话以及它的视图，重新打开应用时两者都会恢复。如果你刻意请求进入线程，它依然会给你线程。
- **打字不再每敲一个键就写入磁盘了。** 以前每个字符都会同步地、以 JSON 的形式将应用中的每一个草稿保存在主线程上——而这正是需要跟上你打字速度的线程。你写的内容依然会立即反映在应用中；但磁盘最多每 400 毫秒才会知道一次，并且当窗口关闭或失去焦点时会立即保存，所以什么都不会丢失。
- **通知面板打开时不再带着一个已经显示出来的提示框。** 以前打开它时会将焦点移到第一个图标按钮上，而提示框不仅在悬停时显示，在获得焦点时也会显示。
- **留在评审中的卡片可以回来了。** 看板在每次启动时都会重新与它的执行记录同步，但这仅限于状态为 *进行中* 的卡片。如果是停在 *评审中* 的卡片，且该评审随着应用关闭而死掉——或者其执行记录因为历史被修剪而丢失——它就会永远留在那里。现在，它的读取方式与实时流程相同：通过审批的去列表中，需要修改和失败的退回给你，而如果是有人手动拖到那里的卡片，那依然只由该人负责。
- **聊天中的代理和任务中的代理是同一个了。** 之前，聊天会用西班牙语构建自己的系统提示词，里面没有 `ask` 块——所以与你对话的代理无法要求你做决定——并且每一个 skill 都被完整粘贴进去，而不是指向代码库中的文件。现在，聊天都经过同一个构建器：相同的个人资料、相同的共享上下文、相同的 skill、相同的提问方式，只是去掉了代理在对话中用不到的看板和委派。
- **应用从头到尾都在说你的语言了。** 之前，界面被翻译了，但底层有大约三十条消息没有被翻译：停止的执行、审批、被拒绝的委派、失败的 hook、手机收到的错误、被中断的执行留下来的内容，以及无法安装的 CLI。在英语窗口中，它们全都是西班牙语。现在，它们和所有其他内容一样通过相同的词典输出——并且如果昨天的执行是在另一种语言下被中断的，今天依然会被识别为已中断。
- **不点名的委派不再会让任务挂起了。** 如果规划器拼错了代理的名字——或者命名了一个不归它管的代理——它就会一直等待一个永远不会到来的团队，它的卡片也会一直卡在 *进行中* 直到应用重启。现在，错误会带着它可以实际使用的名字返回给规划器，以便它重新委派；如果没有更多轮次可用，任务就会以需要你处理的状态关闭，而不是假装在工作。
- **连启动都启动不了的执行会关闭它的卡片。** 以前，如果缺少 CLI，执行会报错，但看板永远不会知道这件事。
- **触及轮次上限时会通知你了。** 任务现在会以需要你处理的状态关闭，细节中会标明触及了上限，并伴随着任何故障都会收到的相同通知，而不是像完成了任务一样悄悄结束。
- **忘记如何委派的规划器。** 只有在开启会话的那一轮才发送说明，对于描述性内容（角色、配置文件、共享上下文、skill 列表）是正确的，但对于代理赖以*行动*的两个块来说却是错误的。随着会话的增长，CLI 会压缩其自身的上下文，而一旦 `delegate` 块被总结掉，规划器就无法再联系它自己的团队了：它会去寻找一个 `ainess` 命令行和一个 MCP 工具，并最终要求用户代为委派，把它运行于其中的应用当成别人的东西来思考。现在，`delegate` 和 `ask` 块会在每一轮都发送。它们是协议，而不是开场白。
- **应用崩溃不再会让代理在背后偷偷工作了。** 正常关闭应用会终止每个代理进程；而崩溃——任务管理器强杀、断电、系统内核崩溃——永远走不到这一步，所以 CLI 还会继续运行：继续编辑工作区，继续消耗配额，根本没人读取它们的输出，而启动它们的应用早就消失了。现在，每次执行都会记录它背后的进程，下一次启动时会找到它们，将它们停止，并告诉你这件事，这跨越了所有的项目——包括那些在启动时不加载的项目，它们的记账可以等，但进程不能等。单纯靠 pid 来杀进程永远不够：pid 会被重新分配，下一个占用者有可能是你自己的开发服务器，也有可能是个代理。所以，只有当一个进程的镜像*和*它的启动时间依然与记录它的执行记录相匹配时，才会被停止。
- **每个项目都会记住你离开它时的视图。** 以前看板、对话和层级结构是所有项目共享的一个设置，所以如果在层级结构下打开一个项目，然后回到另一个项目，那里也会显示层级结构。现在每个项目都保留自己的设置——这跨越了应用的重启，并且重新打开应用时会落在它最后所在的那个项目。点击一个聊天依然是明确的目的地指令，并且会打开对话。
- **在对话中选定的模型会跟着对话一起被记住。** 以前如果你选了一个模型，去了看板再回来，它又会显示“默认模型”，而下面那个输入框里还留着你刚才打的字。现在它会按对话进行保存，和草稿放在一起，也包括手动输入的模型。
- **机器事件上的 hook 不再询问两次代理了。** 之前，“指示代理”的动作放在一个同样会列出代理的过滤器下面，所以同一个对话框里会有两个意义不同的代理选择器。在一个机器事件上——比如时钟、网络连接、文件变动——代理做过的任何事情都不会触发 hook，所以对代理进行过滤只能意味着“永远不触发”：这些选项从那里被移除了，只留下动作本身的选择器作为唯一的一个，并且带有一个代理的 hook 会回退到该代理所属的项目。现在这个过滤器也根据它的功能命名了（“监听于”）。
- **代理回答中的链接曾把整个应用带到了 `tauri.localhost`。** 代理会写两种类型的链接，而应用把它们当成了一种来处理：一个是网址，另一个是它们正在处理的代码库内部的路径（如 `src/lib/foo.ts`，`README.md`）。后者不是用来打开的，如果留在一个 `<a href>` 上，桌面窗口就会跟随它——直接跳到 `tauri.localhost/src/lib/foo.ts`，导致应用在你眼皮底下消失。现在只有真实的地址才是链接，并且它们会在真实的浏览器中打开；代码库路径则作为你可以阅读的纯文本保留。至于 `javascript:` 或 `data:` 链接——代理可能会有意或无意地写出——从一开始就绝对不会变成链接。
- **当父级告诉它时，代理以前无法切换模型。** 规划器为任务指定一个 `model` 的要求，只有当设置里的“选择模型”打开时才会被遵守。所以如果这个设置关闭——就像默认情况那样——一个被命令换个模型重试的实现者（因为它自己的配额用光了），依然会悄悄地使用同样已经耗尽配额的模型重新启动。现在，不管怎样，父级请求的模型都会被尊重；该设置决定的是是否*告诉规划器去选择*一个模型，而不是它的选择是否算数。并且，子级配额耗尽后不再会像一堵 CLI 错误文本墙一样传给父级：它会被清楚地说明，并附带同一个 CLI 旗下仍然值得一试的模型——它自己的家族被排除在外，因为配额是按家族消耗的——并提醒任务可以携带一个 `model`。当 CLI 没有其他模型时，会告诉父级进行提示，而不是重试。


## 0.7.0 — 2026-09-08

### 新增

- **技能在用得上的时候才打开，不再倒进每一次运行。** 以前一个技能会整份塞进每个启用了它的智能体的系统
  提示里：五个技能就是每次运行里的五本手册，不管读不读。现在每个技能写入
  `.ainess/skills/<名称>/SKILL.md`，提示词里只带它的名字、一行说明用途，以及那个路径 —— 智能体打开与
  手头工作相关的那一个，技能需要的其他东西（脚本、模板）也可以放在同一个目录里。它就是靠那一行说明来
  决定的，编辑器现在也这么写着。
- **通知有声音了。** 两个短音，需要你时上行，做完了时下行，不用看就能分辨。声音由应用自己合成 —— 安装
  包里没有音频文件 —— 在窗口里、从托盘（应用在那里继续活着，这正是声音能传到你这里的原因）以及在手机
  上听起来都一样。配置 → 通用可以关掉，它的编辑器能调音符、波形和音量，也可以换成你自己的声音文件。
- **每个智能体的历史，就在项目里。** `.ainess/history/` 每个智能体一个文件，每一轮结束时追加：谁在问、
  问了什么、回来了什么，委派的工作和聊天都算。应用把全部内容留在自己的存储里，只有它能读；这个文件是
  明天回来的智能体、以及打开编辑器的你，唯一的入口。文件满了会整轮整轮地丢弃，绝不砍掉半轮。
- **终端标签页可以拖成你想要的顺序**，和任何带标签页的编辑器一样：拖着的那个会变淡，一条线显示它会落
  在哪里。
- **钩子可以挂在机器自身的状况上。** 在此之前钩子只回应智能体做了什么。现在多了五个事件回应机器：应用
  启动、时钟（在某个时刻，或每隔多少分钟）、网络断开与恢复，以及项目目录里的文件发生变化 —— 最后这个
  搭在本来就有的监视器上，所以噪音（`.git`、`node_modules`、构建产物）传不进来。它们只在应用打开时运
  行，每个最多一分钟一次，作用的项目取自钩子自己的过滤条件，或者当前打开的那个。本来就会触发的
  `approval.requested` 终于出现在可选列表里了。
- **更新日志用你的语言。** 更新之后弹出的对话框，以及配置 → 关于，现在显示翻译过的说明。英文留在
  `CHANGELOG.md`，其他每种语言各有自己的文件，发布检查会盯着它们跟上正在发布的版本。
- **每五分钟找一次新版本**，不只是启动时找一次，这样应用开着的时候发布的版本，当天就能到你手上。还是
  一样的提示，配置里还是同一个开关可以关掉。
- **打断一轮来说点什么。** 等着某个智能体的消息多了第二个按钮：停掉正在跑的，立刻把消息交过去。没有任
  何重复 —— 智能体做过的在磁盘上，说过的在它自己的会话里，下一次运行会接着那个会话 —— 而且会告诉它这
  一轮被打断了，免得它把记录当成一轮已经完成的。
- **输入框里的命令。** 在空的输入框里打 `/` 会打开一份短清单：`/compact` 让项目里所有智能体开始新会话
  —— 什么都不会丢，因为每个都被指向自己在 `.ainess/history/` 里的文件，只回读新工作需要的部分 ——
  `/cost` 打开这个项目花了多少。输入框里其他任何内容都是消息，所以「看看 Claude 的 /compact」还是原封
  不动地发给团队。

### 修复

- **指令在每一轮都被重新发送。** 一个智能体的开场白 —— 它的角色、`delegate` 和 `ask` 的格式、共享上下
  文、个人资料、技能清单 —— 会跟着一段 CLI 本来就在往下带的对话的每条消息一起走。在 Claude 上，这是同
  样的段落一轮一轮地计费；在把指令放进提示词里的那些提供方（Antigravity、Copilot、opencode 等）上，还
  会在记录里再留一份副本，永远留着，所以一段长会话为此付了很多次钱。现在它们只走一次，在开启会话的那
  一轮。仍然每轮都走的是看板，因为那是会变的部分。
- 项目可以在文件管理器里打开自己的目录，右键菜单和三个点都能 —— 而且这两个菜单在它们是同一样东西的地
  方，现在提供完全相同的动作。以前项目的路径只在右键里，不在三个点里，而聊天的「打开」正好相反。
- 一个项目不能再在根部放两个编排者。团队对话框会要求给第二个指定一个父节点，那本来就是它该在的位置：
  并排放着时两个都会读整个看板、都可能拿走同一张卡，只有第一个是输入框、CLI 和手机写入的默认目标，而
  项目里唯一那个「进行中的任务」指针会让一个覆盖另一个 —— 第一个任务的卡片没被移动、钩子没跑、通知也
  没有。已经有两个的团队，一打开其中任何一个就会告诉你。
- 换掉一个智能体的 CLI 时，旧的那个会话被保留了下来，下一次运行把 Claude 开的会话 id 递给了
  Antigravity —— 当场就失败，因为那是另一个从没听过的名字。现在 CLI 变了会话就被丢掉，智能体进入或离
  开自己的 worktree 时也一样，那是会话所绑定的另一半。
- 仓库监视器不再被应用自己的 `.ainess/` 目录吵醒：看板、团队，还有现在的历史，都是在工作过程中写进去
  的，文件钩子会变成在回应应用而不是用户。
- 钩子以前会问两遍它作用在什么上：一个字段填智能体，另一个填项目。现在只有一个 —— 全部、整个项目，或
  者项目里的某个智能体 —— 因为一个智能体只属于一个项目，这一对要么彼此重复，要么互相矛盾到永远不触发。
- 那些跨项目的智能体列表 —— 钩子要指示的、钩子过滤到的、保存的指令绑定的 —— 现在按各自所属的项目分组，
  带着项目的颜色。以前两个项目各有一个「编排者」，看起来一模一样。
- 你亲自写信的智能体，会被告知它是谁。以前不管工作来自它的规划者还是来自你，它读到的提示词都一样，于
  是实现者会把你的消息又委派出去 —— 然后停在「等待它的团队」。
- 而那种等待本来也结束了：一份委派指名了不在这个智能体手下的人，会让它一直等一个永远不来的团队。当一
  份都没落地时，智能体就重新空闲了。
- 终端里的链接一下点击就能打开。以前只有 CLI 自己标记过的才算链接，而且还得按住 Ctrl；现在输出里任何
  URL 都算，并且会在真正的浏览器里打开。
- 在手机上，键盘会挡住你正在写字的输入框。页面在键盘弹出时故意不改变自己的尺寸 —— 那会让对话在工作到
  一半时脱离底部锚点 —— 所以改成把应用缩短键盘占掉的那么多。
- 「有新版本」的提示条把发布说明照原样显示出来，于是读到的是 `[CHANGELOG.md](https://…)`：提示条没有
  markdown 可以拿来渲染它。它现在只说该说的，改了什么在更新之后打开的更新日志里。
- 智能体工作时写下的消息只出现在「通讯」里，别的地方都看不到，像是被应用吞掉了。现在它待在对话的末尾，
  虚线框加一个时钟，写着它在等谁，轮到它之前还可以收回。
- 这条消息还可能被交得太早：会委派的智能体在它的团队做完之前就结束了自己的运行，队列在那时被清空 ——
  消息和它本该跟在后面的工作并排跑了起来。现在它会等到智能体真正空下来。
