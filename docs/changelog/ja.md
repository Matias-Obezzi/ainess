# 変更履歴

0.6.0 より前のバージョンは、リポジトリの CHANGELOG に英語で残っています。

## 未リリース

### 追加

- **返事を待っているものがあるとき、タスクバーのボタンが点滅します。** 承認や質問は、あなたが戻るまで
  エージェントを止めたままにします。これまでは、それを知る方法は見ていることだけでした。点滅するのは
  ウィンドウが前面にないあいだだけで、その判定はウィンドウのある側で行います。尋ねてから動くのでは、
  その隙にユーザーが戻ってこられてしまいますし、すでにウィンドウを見ている人に向かって点滅する
  タスクバーは、点滅しないより悪いからです。この二つだけです。終わったタスクは知らせであって、
  止まったエージェントではありません。

- **サイドバーが、無人で動いているプロジェクトに印をつけます。** 自律モードのあいだ、名前の横に月が
  出ます。もともとプロジェクトごとのもので——スイッチはそのプロジェクトにしか効きません——ただ、
  それを伝える場所がプロジェクトの中にしかありませんでした。見ていないプロジェクトには役に立ちません。

### 修正

- **右のドックは、いま開いているプロジェクトのものです。** あるプロジェクトでターミナルのパネルを開いて
  別のプロジェクトに移ると、そちらでも開いたままでした。しかもタブは空です。ターミナルは最初の
  プロジェクトのものだからです。三つのパネルはプロジェクトごとに覚えられるようになりました。離れるときに
  しまわれ、戻ってくると出てきて、一度も開いていないプロジェクトでは閉じたままです。


## 0.11.0 — 2026-09-10

### 追加

- **プロジェクトの三つのビューが、サイドバーの行になりました。** オーケストレーター、タスク、階層は上の
  バーの切り替えでした。あのバーはプロジェクト名も、ブランチも、使った金額も、自律モードのスイッチも、
  すべてのパネルの開閉も抱えている唯一の帯です。これらはナビゲーションであり、ナビゲーションは左の列に
  住むものです。各行は自分の名前のビューを開きます。プロジェクトが前回どこで終わったかに任せません。

- **クイックコマンドは自分のものでもよくなりました。** 検出されたスクリプトの隣に、どのファイルも宣言して
  いないものを足す場所ができました。docker compose の一行、トンネル、このプロジェクトだけに要る
  マイグレーション。プロジェクトに保存され、メニューの先頭に並びます。

- **ウィンドウのバーが、チャットの経路がつながっていることを知らせます。** 電話の隣に、Telegram・Discord・
  Slack のいずれかが実際に動いているときだけ灯ります。これまでは設定を開いて確かめるしかなかった問いです。
  スイッチではありません。経路を有効にするにはトークンと、誰が話してよいかの名簿が要ります。

- **ターミナルのパネルが、プロジェクト自身のスクリプトをボタンで出すようになりました。** 開発サーバーを
  立ち上げるには、ターミナルを開いて、プロジェクトにすでに書いてあることを打ち直す必要がありました。これからは
  パネルがそれを読みます。package.json の `scripts`、Makefile のターゲット、そして cargo のいつもの四つです。
  ひとつにつきひとつのボタンで、よく使うもの——dev、start、build、test——が前に来ます。それぞれが自分の
  タブを開き、「PowerShell 3」ではなくスクリプトの名前がつくので、サーバーのいるタブは後から見つけられます。
  すでに動いているスクリプトを押すと、二つ目を立ち上げてポートの取り合いに負けるのではなく、そのタブに
  移動します。動いているものには緑の点がつきます。パッケージマネージャはロックファイルから決めます。pnpm の
  ワークスペースで `npm run` を使うと別のツリーを解決してしまうからです。名前が単純な名前でないスクリプトは
  そもそも出しません。これらの文字列は本物のシェルに打ち込まれ、`predev && curl x | sh` は書いてあるとおりに
  走ってしまうからです。

- **依存関係の図は、タスクから開くようになりました。出るのはそのタスクの家族だけです。** これまでは
  ボード全体のもうひとつの表示で、プロジェクト中のすべての連なりを横に並べて描いていました。ウィンドウより
  横に広がってしまい、「これは何と絡んでいるのか」の答えはその真ん中のどこかに埋もれていました。今は
  タスク自身から開きます。画面にあるのは、そのタスクが待っているものと、そのタスクを待っているもの——
  たどれるかぎり——だけです。前提をたまたま共有しているだけのタスクは兄弟であって家族ではないので、
  入りません。その兄弟たちこそ、前のものを読めなくしていた当のものでした。カードをクリックすると図が
  そこへ移るので、連なりを一歩ずつたどれます。アーカイブ済みのものも一緒に出ます。アーカイブされた前提も、
  その下のものが始められない理由であることに変わりはないからです。

- **会話を巻き戻す、あるいは聞き方を書き直す。** チャットのメッセージを右クリックすれば、そこで会話を
  終わりにできます。自分のメッセージなら、書き直してそこから聞き直すこともできます。後に続いていたものは
  消え、エージェントのセッションも消えます。目に見えるスレッドは会話の半分でしかなく、もう半分は
  エージェントの記憶だからです。取り消したはずのものを記憶に残したままにすれば、次の答えが何の上に
  立っているかについて、スレッドが嘘をつくことになります。ダイアログはそれをボタンの前に伝えます。
  最後のメッセージまで戻す項目は灰色です。何も持っていかないからです。

- **自律モード。切れる時刻つきです。** プロジェクトのバーにあるボタンで、1・2・4・8・12
  時間のどれかをオンにします。オンのあいだ、プロジェクトはあなたを待ちません。承認が要る委譲は承認され、
  質問はいちばん慎重な線で自分で答えられ、ラウンド上限がタスクを閉じることもなくなります。「ずっと」はありません——
  決めた時刻に自分で切れますし、手で止めればこれまでどおり止まります。プロジェクトの上限金額はこれまでと同じく効いています。
  ブレーキはそちらです。質問ばかりするタスクが一晩を食いつぶすこともありません。自動の回答が十回を超えると、
  質問はまたあなたを待つようになります。終わるとき、何が終わり、何が失敗し、あなた抜きで何を承認し何に答えたかの報告が
  スレッドに残ります。

- **クォータが戻ったら、もう一度。** モデルのクォータ切れで落ちた実行は、あなたが戻って再試行を押すまで仕事を
  宙ぶらりんにしていました。エージェントごとにチェックボックスができました。クォータが尽きたら実行は失敗せずに待ち、
  プロバイダに空きができ次第、同じプロンプトで自分から再開します。自律モードならチェックの有無にかかわらずそうなります。
  クォータが戻った時点でチェックが外れていたり、自律モードが終わっていたりすれば、何も再開せず、黙るのではなく
  そのことを伝えます。

- **Slack も入って、これで三つそろいました。** Telegram、Discord、Slack——すでに開いているどれでも同じ
  コマンドが使えます。設定にはそれぞれのカードと、それぞれのチャット名簿があります。ひとつで許可された
  チャットは、そのひとつでだけ許可されています。Slack はトークンをひとつではなく二つ求めます。接続を開く
  アプリレベルのものと、書き込むボットのものです。これは Slack の設計であって私たちのものではありません。
  どちらがどちらかは画面が伝えます。Slack アプリで Socket Mode を有効にし、ボットをチャンネルに招く必要も
  あります。それも画面に書いてあります。でなければ何も届かず、ここからは理由を伝えるすべがないからです。

- **Telegram の隣に Discord。** 二つのうち、すでに開いているほうで同じコマンドが使えます。書いたことは
  タスクになり、`/status` は誰が動いているかを答え、`/approve` と `/answer` はあなたを待っているものを
  片づけます。設定にはチャンネルごとのカードが並びました。どちらも何も外に開きません——出ていくのはアプリの
  ほうなので、トンネルもポートも、見つけられる住所もないままです。各チャンネルは自分のチャットだけを許可
  します。Discord のチャンネル ID が、Telegram の名簿に載っているからといって許可されることはありません。
  ボットには Discord の開発者ポータルでメッセージ内容のインテントを有効にする必要があり、画面もそう伝えます。
  それがないとメッセージは空で届き、ここからは理由を知るすべがないからです。

- **プルリクエストをここから開けます。** エージェントが自分のブランチで終わったあと、最後の一手はあなたが
  手でやるものでした。これからは pull と push の隣に、そして完了したカードの上にボタンがあります。
  ワンクリックで開くことは決してありません。ダイアログが、どのブランチがどれに向かうかを示し、タイトルと
  本文はタスクと、エージェントが報告した内容——触れたファイル、検証したこと、そしてできなかったこと——から
  すでに書かれています。できなかったことは省かれず、専用の見出しで入ります。既定のブランチでは断りますし、
  push していないブランチでは、黙って push するのではなく先に push するかを尋ねます。

- **タスクを別のモデルで、あるいは別のエージェントでやり直せます。** 失敗した実行や、途中でエージェントの
  残量が尽きた実行は、全部打ち直すしかありませんでした。これからは実行のメニューと、そのカードのボタンから、
  同じプロンプトのまま、選んだ相手でもう一度走らせられます。失敗した実行の続きではなく、ゼロから始めます——
  たいていはその実行の文脈こそが問題だからです。エージェントを変えるとモデルは選び直しになります。
  あるプロバイダのモデルは別のプロバイダのモデルではなく、引き継いでしまうと、存在しないモデルへ実行を
  送ることになるからです。

- **入力欄にファイルを落とせます。** クリップと Ctrl+V が二つの入り口でした。すでに開いているフォルダーから
  ファイルをドラッグしてくるのが三つ目で、遠回りのいらない方法です。ファイルを載せたドラッグが上に来ると
  入力欄が縁取られ、すでに書いてあったものも一緒に送られます。列から列へ移動中のタスクカードが通りかかっても
  そのままです——運んでいるのはテキストであってファイルではないので、受け取ってもどこにも動きません。

### 修正

- **長い詳細が、ほかのすべてをダイアログの外に押し出すことはなくなりました。** エージェントは書きたいだけ
  書きますし、詳細は状態の欄と、依存関係と実行のあいだに置かれています。これからは数行に畳まれ、「もっと見る」
  で開きます。ボタンが要るかどうかは文字数から推測せず、実際に測ります。段落が何行になるかは、与えられた幅
  次第だからです。

- **プロジェクトのスクリプトは、横スクロールする行ではなくメニューになりました。** もともと狭いパネルに
  ボタンを並べれば横スクロールバーになり、スクリプトが二十あるプロジェクトはそのうち十九をその向こうに
  隠していました。これからは「+」の隣のメニューで、シェル選択と同じ形をしています。

- **上のバーは、何体のエージェントが働いているかを言わなくなりました。** サイドバーのプロジェクトの隣の点が
  働いているあいだ息をしています。何が起きているかを見にいく場所は、そちらです。

- **自律モードのボタンは、まわりのボタンと同じ形になりました。** 見逃されないように自分だけ琥珀色の塗りを
  持っていました。その必要はありません。うるさいのはバーの下の帯のほうで、幅いっぱいに走り、モードが
  オンのあいだしか存在しません。

- **コミュニケーションのパネルは吹き出しになりました。** アイコンはパネルがどこに開くかを描いていましたが、
  それはこのパネルについて言えることのうち最もどうでもいいことです。中にあるのは、エージェントたちが
  互いに言ったことです。

- **ボードのツールバーの高さと角がそろいました。** Button と Input と SelectTrigger は既定の角の丸さが
  一致しません。三つで組んだ行には、二種類の丸みが隣り合って並んでいました。これからは高さも丸みもひとつ
  ずつ、既定任せにせず各コントロールに書いてあります。

- **質問に答えるのは、印をつけるリストと、押すボタンになりました。** これまで選択肢は横並びのボタンで、
  それぞれが自分の文字の幅しかありませんでした。並べるとがたついて見え、一語の選択肢はその一語の大きさの
  的でしかありませんでした。これからはリストです。一行にひとつ、枠いっぱいの幅で並びます。複数答えられる
  質問はそう書いてあります。二回クリックして気づくものではなくなりました。そして答えがひとつの質問も、
  選択肢に触れた瞬間に送られることはなくなりました。どちらも「送信」を待つので、これから言うことが、
  言う前に画面に出ています。押し間違いは、もう送られてしまったものではなく、もう一度押せば戻るものです。
  答えがひとつの質問では、選択肢と自由記入欄は互いに置き換わります。ひとつの答えが、同時に別の文でも
  あることはできないからです。

- **タスクの下部のボタンが、役割ごとに並びます。** 「間隔をあけて配置」だけを指示された三つのボタンの
  せいで、「アーカイブ」が真ん中に取り残され、別の場所へ連れて行くリンクと、戻ってこない削除から等距離に
  置かれていました。別の場所へ行くものは左、タスクを変えるものは右に、まとめました。

- **ボードから表示の切り替えが消え、「新しいタスク」が本来の場所に戻りました。** 図がボードのもうひとつの
  表示でなくなった以上、切り替える相手がいません。ふたつあったツールバーはひとつになりました。検索、
  フィルタ、件数、そして最後に「見直す」「Markdown としてコピー」「新しいタスク」が並びます。

- **Antigravity のクォータが、なぜ推測なのかを説明します。** ほかのどのプロバイダも数字を出すところで、
  Antigravity のリングにはダッシュが出ます。理由の添えられていないダッシュは、壊れているように見えます。
  壊れてはいません。Antigravity は残量を報告しないのです。正確な数字自体は存在します——その CLI は
  Google に問い合わせています——が、有料の Code Assist ライセンスの向こう側にあり、持っていない
  アカウントは拒否されます。ですからアプリはそれを、ダッシュの隣で、入力欄のポップオーバーでも、
  エージェントの画面でも、設定でも伝えます。表示されているものは引き続き、実行が返してくる
  「quota reached, resets in 1h45m」から推測したものです。読めるものはそれしかありません。

- **クォータのリングとバーは、使うほど埋まっていきます。** これまでは*残り*で埋まっていました。手つかずの
  クォータは満杯のリング、使い切りかけのものはほとんど空——消費されるものの目盛りとしては逆で、ひと目で
  読めなかった理由がこれです。これからは空から始まり、使った分だけ埋まります。隣の数字も同じものを数えます。
  「83%」は使った分であって、残りではありません。色は引き続き残りを見ているので、ほぼ満杯のリングは同時に
  赤でもあります。片方が手遅れになってから言うのではなく、両方が同じ瞬間に「なくなりかけている」と言います。

- **ステップは、ブラウザを待たずに何をしたかを教えてくれます。** エージェントの活動の行はどれも切り詰められて
  います——ツールは要約を、委譲はタスクの九十文字を。残りを読む手段はブラウザの `title` だけでした。一秒の
  待ち、ポインタのあった場所に出る素っ気ない箱、そして改行が空白に潰される——コマンドやスタックトレースには
  いちばん困る挙動です。これからはアプリ自身のツールチップです。その行に固定され、等幅で、改行はそのまま。
  実行中のステップにも付きました。こちらは今まで何もありませんでした。

- **誰も話していないプロジェクトのことを、エージェントが知っていることはもうありません。** 共有コンテキストは
  設定画面のひとつのテキストで、すべてのプロジェクトのすべてのエージェントのプロンプトに足されていました。
  あるリポジトリのことを書けば、どこにいるエージェントもそれを読んでいたのです。ひとつのプロジェクトに宛てた
  メッセージが別のプロジェクトで理解され、実行され、持ち込まれたのはそのためでした。これからはプロジェクトごとの
  ものです。設定画面でどれかを選び、`ainess context` も CLI のほかと同じく `-p`/`-w` を受け取ります。
  これまで書いていた内容は既存の各プロジェクトに複製されるので、失われるものはありません。その文章が一つの
  プロジェクトのものだったなら、ほかのプロジェクトが今それを消す場所です。

- **フックは、選んだイベントの話から始まります。** 十七のイベントの裏に既定の文面はひとつしかなく、
  しかも「エージェントが終わりました」向けに書かれ、スペイン語で固定されていました。「インターネットが切れた」
  のフックが、誰に対しても、多くの人が選んでいない言語で、エージェントが終わったと告げて始まっていたのです。
  これからは各イベントが自分の一行から始まります。あなたの言語で、そのイベントが実際に持っている変数を使って——
  質問なら質問を、クォータ切れならモデルを、委譲なら両方のエージェントを。メッセージに触れる前に
  イベントを変えれば文面もついてきます。触れたあとはついてきません。そこからはあなたのものだからです。
  テストボタンもあなたの言語で変数を埋めるので、プレビューは実際に届くメッセージそのものです。

- **表示していない六つの言語を、アプリが抱えて回るのをやめました。** 七つの辞書が同じバンドルに入っていた
  ため、起動のたびに、誰も読んでいない六つ分を支払っていました——575 kB、圧縮して 179 です。これからは
  スペイン語だけが組み込まれ（ほかのすべての言語が最後に戻る土台です）、あなたの言語は最初の描画より前に
  取得されて、そのまま保持されます。このチャンクは 575 kB から 83 kB に、圧縮後は 179 から 27 になりました。

- **チャットで質問に答えたエージェントが、仕事を配れなくなりました。** あなたの回答を運ぶターンは、
  それがチャットのものだと告げられないまま始まっていました。そのためタスクとして読まれ、`delegate`
  ブロックが解釈されて実行されていたのです。誰も頼んでいない会話の中から、エージェントがほかの
  エージェントを働かせることができてしまっていました。

- **ドラッグ中、ボードは横だけでなく下にもスクロールします。** 画面より高い列には、ボードが横方向で
  抱えていたのと同じ問題がありました。落としたい相手のカードが画面の外にあるのです。これからは
  ポインタの下にある列も、同じ加速の仕方で引っぱります。

- **エージェントが作業中に開いていたコンソールウィンドウは、これで本当になくなりました。** 前回の修正は
  違うほうの半分を直していました。「コンソールなしのプロセス」を頼むのは、そのプロセスには効きます——
  ですが今度は、そのプロセスが動かすコンソールプログラムのほうが Windows にコンソールを求め、新しいものを
  与えられ、それが見えていたのです。あの窓は一度も私たちのものではありませんでした。エージェントが
  動かしていたプログラムのものでした。これからはアプリが起動時にコンソールをひとつだけ確保して隠し、
  その下にあるものはどれだけ深くても、自分の分を求めるかわりにそれを受け継ぎます。

- **回答の中のファイルリンクが、何かをするようになりました。** エージェントが
  `[そのファイル](file:///C:/Users/you/notes.txt)` と書くと、灰色の死んだ文字が描かれるだけでした。
  `file:` が `javascript:` や `data:` と同じ拒否リストに入っていたからです。あちらはページ内で実際に

- **カードを端まで持っていくと、ボードのほうがスクロールします。** ウィンドウより広いボードは横切れません
  でした。目当ての列は画面の外にあり、スクロールしようと手を離すと、意図しない場所にカードが落ちるからです。

  そのことを教えてくれないからです。

### 追加

- **空のボックスが何かを語り、変化するようになりました。** composer のプレースホルダーが5つのパターンのうちの1つを入力し、数秒ごとに切り替わります。チームの目的、何を任せられるか、`/` でコマンドが開くこと、そして Enter のショートカットについてです。これは行にずっと残るものではなく、一度だけ読むものになりました。システムに動きを減らすよう求めている人向けには静止したままで、スマートフォンでは全く動きません。
- **意味のある場所でのみ動きます。** まだ進行中の実行処理は、スピナーの代わりに現在のステップの上を光が通り抜けます。ホームの「現在作業中」は生きているように見え、承認のピルは、何かあなたの返答を待っている間（その間だけ）周囲に光の糸をまといます。そして使用量パネルの金額は、テーブルで使用しているのと同じ通貨フォーマットで実際の金額までカウントアップします。それ以外は何も装飾されていません。スレッド、フィード、ボードは静止したままです。一日中見ているツールは、何かを伝えている時にだけ動くべきだからです。

- **そして、実際に何をしたかで締めくくります。** 触れたファイル、それらをテストするために何を実行したか、そして何ができなかったかを示す `result` ブロックです。散文は残りますが、これはプランナーが解釈なしに読む部分であり、実行の詳細に3つの短いリストとして表示されます。
- **ホームは、何が待っているかを知る場所です。** プロジェクトの上部に、すべてを横断する2つのリストがあります。承認待ちで止まっている委任、誰も答えていない質問、ボードが *対応が必要* に残したカードなど「あなたを待っているもの」。そして、「誰が今、何に、いつから取り組んでいるか」です。各行は、承認や質問のためのスレッド、あるいはタスクのためにカードが開かれたボードなど、その事柄がある場所へとあなたを導きます。どちらも中身がない時は消えるため、静かなホームはいつもと同じように見えます。そして、最後に開いたプロジェクトを示していたバッジはなくなりました。あなたがホームにいるのは、まさにそこにいないからです。代わりに、各カードにはその中で何が起きているかが書かれています：「2 件作業中 · 1 件対応待ち」。
- **同じタスクにいるエージェントが互いを知るようになりました。** 2人の実装担当者に作業を分割するプランナーは、両者を盲目的に開始させていました。どちらも相手がいることを知らず、両方が同じファイルに手を伸ばし、プランナーは矛盾する2つの回答を受け取っていました。それぞれに、他に誰がこの同じタスクに取り組んでいるのか、何を求められているのか、そして他人が手にしているものは彼らが変更するものであり、あなたが上書きするものではないことが伝えられるようになりました。これは作業中に変わる性質のものなので、ボードと同じように毎ターン伝達されます。
- **フックが名前ではなく「ボス」に書けるようになりました。** 指示を出すエージェントとして、階層のトップ（プロジェクトのルートプランナー。composer、CLI、スマートフォンがデフォルトで書き込むのと同じエージェント）を指定できるようになりました。これは保存時ではなくフックが発火した時に解決されるため、チームを再編成しても、もう担当していない人を指したままになることはありません。フィルターをかけずに放置すれば *すべて* のプロジェクトのボスに届くため、スケジュールされた1つのフックで全プロジェクトをカバーできます。1つのプロジェクトに絞ればそのプロジェクトのボスになり、エージェントが引き起こしたイベントは、それが起きたプロジェクト内に留まります。

### 修正

- **エージェントがまだ書いている間でも、会話を遡って読めるようになりました。** チャットでは、送られてくる差分ごとに一番下まで引き戻されていました。2分前に何を言ったかを確認するために上にスクロールすることは、完了するまで不可能でした。チャットは、オーケストレータのスレッドがすでにやっていたことと同じ動きをするようになりました。あなたが一番下にいる時だけ一番下を追いかけ、そうでない時は、隅にあるピルが何通のメッセージが届いたかを示し、好きな時にそこへ連れて行ってくれます。単純な「新しいメッセージ」ではなく、チャット、スレッド、コミュニケーションフィードの3箇所すべてに件数が表示されるようになりました。

- **composer のボタンがボックス内に群がらなくなりました。** 送信ボタンが時計に変わることはなくなりました（キューへの追加は以前とまったく同じように機能し、エージェントが忙しい時に Enter を押すとキューに入り、ツールチップにその旨が表示されます）。そしてクリップはバーの左側に単独で配置され、エージェント、モデル、承認、クォータは右側に集められました。

- **会話が全体を再描画しなくなりました。** スレッドとコミュニケーションフィードは、持っているすべてのメッセージ（プロジェクトあたり3000件）を描画しており、1行もメモ化（memoize）されていなかったため、ストアに触れるものはすべてを再描画していました。今後は最後の部分だけを描画し、上部にはジャンプするのではなく位置を維持したままさらに遡るためのリンクが用意され、行は自分自身の何かが実際に変更された時にだけ再描画されるようになりました。
- **作業時間が長くなるほどエージェントの入力コストが高くなることがなくなりました。** CLI が送信する各差分は書き込み処理でした。末尾に1文字追加するためにメッセージリスト全体をコピーし、生の行のために実行マップをコピーし、何を保存するか決めるために全メッセージを見直していました。これをトークンごとにやっていました。履歴が長くなると、それはこれまでに言われたすべてに比例した作業になり、まさにこれが、時間が経つにつれてウィンドウが重くなる理由でした。差分は集められて最大 80 ミリ秒ごとにまとめて適用され、実行が終了するか停止された時にはその場でフラッシュされるため、遅れたり見逃されたりすることはありません。

- **タイピングのたびにディスクに書き込むことがなくなりました。** 1文字ごとにアプリ内のすべてのドラフトが JSON としてメインスレッド（まさにタイピングについていく必要があるスレッド）で同期的に保存されていました。あなたが書いたものは引き続き瞬時にアプリに反映されますが、ディスクには最大 400 ミリ秒ごとに伝わり、ウィンドウが閉じられたりフォーカスが外れたりした時はすぐに伝わるため、何も失われません。
- **通知パネルが、ツールチップがすでに表示された状態で開くことがなくなりました。** 開くと最初のアイコンボタンにフォーカスが移動し、ツールチップはホバーと同じくらいフォーカスでも表示されていました。
- **レビューに残されたカードが戻ってきます。** ボードは起動のたびに実行記録と歩調を合わせますが、それは *作業中* のカードだけでした。アプリと一緒に死んだレビューの背後に *レビュー中* として駐車されていたカード（またはトリミングされた履歴から実行記録が落ちてしまったもの）は、永遠にそこに残っていました。今後はライブフローと同じ方法で読み取られます。承認されればリストへ進み、変更や失敗はあなたに戻り、誰かが手動でそこへドラッグしたカードは引き続きその人だけの用件として扱われます。
- **チャットのエージェントがタスクのエージェントと同じになりました。** チャットは `ask` ブロックなしのスペイン語で独自のシステムプロンプトを構築していたため（そのため、会話しているエージェントはあなたに決定を求めることができませんでした）、また各スキルはリポジトリ内の場所を指すのではなく全体が貼り付けられていました。チャットは今、1つの共通ビルダーを通るようになりました。同じプロファイル、同じ共有コンテキスト、同じスキル、同じ尋ね方になり、会話ではエージェントが使わないボードと委任だけが除外されます。
- **アプリが奥深くまであなたの言語を話すようになりました。** インターフェースは翻訳されていましたが、その下の約30のメッセージはそうではありませんでした。停止された実行、承認、拒否された委任、失敗したフック、スマートフォンが受け取るエラー、中断された実行が残すもの、インストールできなかった CLI などです。英語のウィンドウでは、これらすべてがスペイン語で出力されていました。これらも他のすべてと同じ辞書を通るようになり、昨日別の言語でビルドによって中断された実行は、今日も中断されたものとして認識されます。
- **誰も指名していない委任がタスクをハングさせなくなりました。** プランナーがエージェントの名前をスペルミスしたり、部下ではないエージェントを指名したりすると、来るはずのないチームを待ち続け、アプリが再起動するまでそのカードは *作業中* で立ち往生していました。今後は、実際に使える名前とともにエラーがプランナーに戻され、再度委任するように促されます。上限回数に達した場合は、作業しているふりをするのではなく、対応が必要な状態としてタスクが終了します。
- **起動すらできない実行はカードを閉じます。** CLI が見つからない場合、実行はエラーになりましたが、ボードはそれを知る由もありませんでした。
- **ラウンドの上限に達したことを伝えます。** 終わったかのように静かに終了するのではなく、詳細に上限を記載し、他の失敗が受け取るのと同じ通知を伴って、対応が必要なタスクとして終了するようになりました。
- **委任の方法を忘れていたプランナー。** セッションを開くターンでのみ指示を送信するのは、説明（役割、プロファイル、共有コンテキスト、スキルのリスト）には正解でしたが、エージェントが *行動* するための2つのブロックにとっては間違いでした。セッションが長くなると CLI は自身のコンテキストを圧縮し、`delegate` ブロックが要約されて消えてしまうと、プランナーは自分のチームにアクセスできなくなっていました。`ainess` コマンドラインや MCP ツールを探しに行き、結局ユーザーに代わりに委任するよう求め、自分が動いているアプリをまるで他の誰かのもののように推論していました。今後は `delegate` と `ask` ブロックが毎ターン送信されます。これらはプロトコルであり、前置きではありません。
- **クラッシュがアプリの裏でエージェントを働かせたままにすることがなくなりました。** アプリを閉じると各エージェントプロセスは終了します。しかしクラッシュ（タスクマネージャー、停電、パニック）ではそこまで到達しないため、CLI は動き続けていました。ワークスペースを編集し続け、クォータを消費し続け、誰もその出力を読まず、それらを起動したアプリはすでに消えていました。各実行は背後にあるプロセスを書き留めるようになり、次回の起動時にそれらを見つけて停止し、その旨をすべてのプロジェクト（起動時に読み込まれないプロジェクトを含みます。会計処理は待てますが、プロセスは待てないからです）にわたって伝えます。PID だけでは強制終了の判断材料としては不十分です。再割り当てされ、次の所有者がエージェントではなくあなた自身の開発サーバーである可能性も十分にあるため、イメージ *と*
  開始時刻の両方が、記録した実行データと一致した場合にのみ、プロセスは停止されます。
- **各プロジェクトが、あなたが離れた時のビューを記憶します。** ボード、会話、階層はすべてのプロジェクトで共有される1つの設定だったため、あるプロジェクトを階層で開いて別のプロジェクトに戻ると、そこにも階層が表示されていました。各プロジェクトが独自の設定を保持するようになり（再起動をまたいでも）、アプリを開き直すと最後にいたプロジェクトに着地します。チャットをクリックすることは引き続き明示的な目的地であり、会話を開きます。
- **会話で選んだモデルが一緒に記憶されます。** モデルを一つ選び、ボードに行ってから戻ってくると、すぐ下のボックスには入力した文字が残っているのに、再び「デフォルトモデル」と表示されていました。今後は会話ごとにドラフトと一緒に保持され、手動で入力したモデルも含まれます。
- **マシンイベントのフックがエージェントを2回尋ねなくなりました。** 「エージェントに指示を出す」アクションはエージェントもリストアップするフィルターの下にあったため、同じダイアログに意味の違う2つのエージェント選択器がありました。マシンイベント（時計、接続、ファイルの変更）では、エージェントがしたことによってフックが引き起こされることはないため、エージェントでフィルタリングすることは「絶対に発火しない」ことを意味するだけでした。これらのオプションはそこからなくなり、アクション自体の選択器だけが残され、エージェントを持っていたフックはそのエージェントのプロジェクトにフォールバックします。フィルターの名前も、その役割に応じたもの（「リッスン先」）になりました。
- **エージェントの回答にあるリンクが、アプリ全体を `tauri.localhost` に連れて行っていました。** エージェントは2種類のリンクを書きますが、アプリはそれらを同じように扱っていました。ウェブアドレスと、作業しているリポジトリ内のパス（`src/lib/foo.ts`、`README.md`）です。後者は開くものではありませんが、`<a href>` に残されたままデスクトップウィンドウがそれに従い、`tauri.localhost/src/lib/foo.ts` へと飛んでしまい、アプリがあなたの下から消え去っていました。今後は本物のアドレスだけがリンクになり、本物のブラウザで開きます。リポジトリのパスは読めるテキストとして残されます。エージェントが（意図的かどうかにかかわらず）書く可能性のある `javascript:` や `data:` リンクは、そもそも決してリンクにはなりません。
- **親に言われた時にエージェントがモデルを切り替えられませんでした。** プランナーがタスクに `model` を指定しても、設定で「モデルを選ぶ」がオンになっている間しか従われませんでした。そのため、オフ（デフォルト）の状態で、自身のクォータが尽きたために別のモデルで再試行するよう命じられた実装担当者は、同じ枯渇したモデルで静かに再起動していました。親が要求したモデルはどちらの場合でも尊重されるようになりました。この設定は、プランナーにモデルを *選ぶように言うか* を決定するものであり、その選択が有効かどうかを決定するものではありません。そして、クォータが尽きた子が CLI のエラーテキストの壁として親に到達することもなくなりました。それは明確に伝えられ、同じ CLI でまだ試す価値のあるモデル（クォータはファミリーごとに消費されるため、自身のファミリーは除外されます）が提示され、タスクが `model` を持つことができるというリマインダーも添えられます。CLI に他のモデルがない場合は、再試行するのではなく親に伝えるように言われます。

  られていました。Claude では同じ段落がターンのたびに課金され、指示をプロンプトの中に入れるプロバイダ
  （Antigravity、Copilot、opencode ほか）では、記録の中にもう一部の写しが永久に残り、長いセッションはそ
  の分を何度も払っていました。いまは一度だけ、セッションを開くターンに送られます。毎ターン送られ続ける
  のはボードで、そこが変わる部分だからです。
- プロジェクトはファイルマネージャーで自分のフォルダを開けます。右クリックからも三点メニューからも同じ
  で、この二つのメニューは同じものである限りどこでも同じ動作を並べるようになりました。プロジェクトのパ
  スは右クリックにだけあって三点にはなく、会話の「開く」は逆でした。
- 一つのプロジェクトのルートに二人のオーケストレーターを置けなくなりました。チームのダイアログが二人目
  に親を求めます。もともとそこが居場所でした。横に並んでいると二人ともボード全体を読み、同じカードを取
  りうるのに、入力欄・CLI・電話が既定で書き込む先は最初の一人だけで、プロジェクトに一つしかない「作業中
  のタスク」のポインタは一方がもう一方を上書きしてしまい —— 最初のタスクはカードが動かず、フックも走ら
  ず、通知も出ませんでした。すでに二人いるチームは、どちらを開いてもすぐそう言います。
- エージェントの CLI を変えても古いほうのセッションが残っていて、次の実行は Claude が開いたセッション
  ID を Antigravity に渡していました —— もう一方が聞いたこともない名前なので、その場で失敗します。いま
  は CLI が変わったときにセッションを捨てます。エージェントが自分の worktree に入る／出るときも同じで、
  そちらもセッションが結びついているもう半分です。
- リポジトリのウォッチャーは、アプリ自身の `.ainess/` フォルダでは目を覚まさなくなりました。ボードもチ
  ームも、そしていまは履歴も、作業中にそこへ書き込まれるので、ファイルのフックはユーザーではなくアプリ
  に答えてしまっていました。
- フックは対象を二度たずねていました。エージェント用の欄と、プロジェクト用の欄です。いまは一つです ——
  すべて、プロジェクト全体、またはその中の一人 —— エージェントはちょうど一つのプロジェクトに属するので、
  この組み合わせは一致するか、矛盾して永久に発火しないかのどちらかにしかなりませんでした。
- プロジェクトをまたぐエージェントの一覧 —— フックが指示する相手、フックの絞り込み先、保存した指示の紐
  づけ先 —— は、それぞれが属するプロジェクトごとに、その色とともにまとめられます。「オーケストレーター」
  が一人ずついる二つのプロジェクトは、以前は同じに見えていました。
- あなた自身が書きかけるエージェントには、それが誰なのかが伝わります。仕事がプランナーから来ようとあな
  たから来ようと同じプロンプトを読んでいたので、実装者はあなたのメッセージをさらに委譲して答え —— その
  あと「チームを待っています」で止まっていました。
- その待ち自体ももう終わりです。そのエージェントの下にいない相手を名指しした委譲は、決して来ないチーム
  を待たせ続けていました。一件も着地しなかったときは、エージェントは自由に戻ります。
- ターミナルのリンクはワンクリックで開きます。以前は CLI が自分で印をつけたものだけがリンクで、しかも
  Ctrl を押さえておく必要がありました。いまは出力の中のどの URL もリンクで、本物のブラウザで開きます。
- 電話では、キーボードが入力中の欄を覆っていました。ページはキーボードが開いてもわざとサイズを変えませ
  ん —— 以前はそれが作業の途中で会話を下端のアンカーから外していました —— ので、代わりにキーボードが占
  める分だけアプリを縮めます。
- 「新しいバージョンがあります」のトーストが、リリースノートを書かれたまま表示していて
  `[CHANGELOG.md](https://…)` と読めていました。トーストにはそれを描画する markdown がありません。いま
  は言うべきことだけを言い、何が変わったかは更新後に開く変更履歴にあります。
- エージェントが動いている間に書いたメッセージが、コミュニケーションにだけ現れ、ほかのどこにも出ません
  でした。アプリが飲み込んだように見えます。いまは会話の末尾に、破線と時計つきで、誰を待っているかを添
  えて残り、順番が来る前なら取り消せます。
- そのメッセージは早く渡されすぎることもありました。委譲するエージェントは、チームが終わる前に自分の実
  行を終えるので、キューはそこで空にされていました —— メッセージは、後に続くはずだった仕事の横を走って
  いたのです。いまはエージェントが本当に空くまで待ちます。

## 0.6.0 — 2026-09-08

### 追加

- **ファイルがメッセージと一緒に届きます。** 入力欄のクリップ、または Ctrl+V で直接貼り付け。スクリーン
  ショット、PDF、ログ。画像は送る前にサムネイルを、それ以外は名前とサイズを表示し、どちらも取り消せます。
  送信時にファイルはプロジェクト自身の `.ainess/attachments/` にコピーされ、プロンプトはそのパスを運びます
  —— どの CLI も自分が作業しているリポジトリを読むので、これが添付に対してすべてができる唯一のことです。

### 修正

- エージェントが動いているプロジェクトは、その点自体がゆっくり呼吸して知らせます。以前は名前の横にオレンジ
  の数字が付いていて、返事を待っている何かのように見えました —— サイドバー下部の、本当にあなたを必要とする
  琥珀色のバッジだけが、いまはその見た目です。
- 右クリックメニューからの削除が、ダイアログではなくウィンドウ上部のピル、つまり電話向けの形で尋ねていま
  した。アプリの開発中にだけ起き、しかも質問そのものを失うこともありました。
- フックの `{{` の一覧が、名前だけでなく各変数の中身を説明するようになり、矢印キーで一覧がスクロールします。
  以前は八つ目を過ぎると、選択中の項目が見えない位置へ移動していました。
